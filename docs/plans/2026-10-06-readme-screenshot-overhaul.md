## 2. 截图策略

### 2.1 数据口径（**决策项 D1**，先裁后拍）

README 截图会带出两类真实信息：校内课程名 + **教师姓名 + 教室**（如「王星辰 · 教一-202」）、以及笔记正文（含课堂原帧缩略图）。事实基线：**promo.mp4（27s）已于 v0.7.12 随 Release 公开，里面就有全部课程弹层的 1656 门网格、教师姓名、教室与真实课程库画面**——README 用同源截图不构成任何新增暴露。但这是 Andiii 的隐私口径决定，列 D1 三选一。

### 2.2 生产管线：新增 `scripts/readme-shots.mjs`

零新依赖、零新产品代码，在既有两根管线上接「README 机位预设」：

1. **启动与隔离**（照抄 `ui-shots.mjs` 的缝，修其缺口）：`SEU_SUMMARY_DOCS_OVERRIDE` 指向临时目录，拷 `app.db` **+ `attachments/`**（修复点：`ui-shots.mjs:112-115` 只拷三个 db 文件，笔记页时间线配图会全缺；promo 拍法早已证明必须拷附件）。真库与 userData 全程不碰。
2. **钉窗口**：用 `ui-probe.mjs --zoom` 同款 user32 `SetWindowPos` 把 OS 窗钉到 1920×1200（物理）——保证不同机器、不同 DPI 下截图口径一致（zoom = clamp(W/1600,1,2.5)，W=1920 → z=1.2，CSS 视口 1600）。Emulation 只能盖 CSS 视口、量不到缩放效果，这是既有教训。
3. **钉主题**：走完首启闸门后 `document.documentElement.dataset.theme = 'light'`（照抄 ui-shots 的做法：闸门勾选会重读设置、把 DOM 覆盖清掉，所以必须放闸门之后）。
4. **走查机位**：抽 `ui-shots.mjs` 的 Cdp 类/等待助手为公共函数（**只抽不改行为**，原走查输出保持逐字节一致），按 1.3 清单逐机位截图落 `docs/assets/readme/raw/`。
5. **压缩入库**：ffmpeg-static 统一缩到目标宽度（hero 1440 / 网格 720）+ JPEG q≈82（promo 同参数实测：1180px/226KB，文字可读）；文字细的页面（设置）可保留 PNG。产物直接落 `docs/assets/readme/`。
6. **可选机位**：真起 B站任务（`ui-shots --bili` 走的就是公开端点，无账号写入）→ waitFor 阶段推进 → 截图 → 取消（副本库，无副作用）。

### 2.3 体积预算

README 首屏渲染体验要求：**图片总计 < 4MB、单张 < 800KB**。按 promo 参数预估 8+1 张合计约 1.2–1.6MB，达标。

## 7. 风险与边界

- **隐私口径**：D1 未裁不动手；若裁 B，先确认马赛克后文字仍可读再入库。
- **截图过期货**：UI 每改一批而截图不重建，门面就开始撒谎——批4 的 AGENTS.md 一行是唯一可靠的防腐烂，CI 不渲染 UI、不做截图门禁（成本不对等）。
