## 1. 你报的两个问题：实锤与修法

### A1 侧栏折叠按钮独占一行（观感）

**实锤**

- 结构原因：`.sidebar` 是 `display: flex; flex-direction: column`（style.css:314-327），折叠按钮是它的**第一个 flex 子项**，靠 `align-self: flex-end`（style.css:332-346）贴右——于是它必然独占一整行。
- 几何实测：按钮 `top 62→86`（24px 高，行内只有它），`.sidebar-head` 从 `top 96` 才开始 → 除按钮自身外还多花 10px 的 flex `gap`，**合计 34px 垂直空间只为放一个图标**。
- 头部行容量实测：侧栏内容宽 **269px**（304 − 12 左 − 12 右 − 11 滚动条槽）；`课程` 30px + `导入 B站视频` 95px + `刷新课程` 71px + 折叠键 24px + 3 个 gap 20px = **240px ≤ 269px** → **塞得进一行，还剩 29px 余量**。

**修法（推荐 D1-A）**：折叠按钮移入 `.sidebar-head`，成为行末（最右）元素；DOM 顺序 `课程 → 导入 B站视频 → 刷新课程 → ◧`。

配套两处必须同时改，否则会回归：

1. **折叠态选择器**：现在 `.sidebar.collapsed > :not(.sidebar-collapse) { display: none }`（style.css:348）会把整行含按钮一起隐藏 → 收起后无法展开。改为「隐藏除 `.sidebar-head` 外的兄弟」+「隐藏 head 内除按钮外的子元素」，收起态用 `justify-content: center` 把按钮居中（48px 窄条内居中，与今天视觉一致）。
2. **busy 标签会撑破一行（实测）**：`刷新课程` 71px → 刷新中显示页数时 `刷新中 12/34 页…` **120px**。一行化后：30+8+95+6+120+6+24 = **289px > 269px**，`.sidebar` 有 `overflow-x: hidden`（style.css:320）→ **按钮会被无声裁掉**。所以必须把 busy 文案收短成 `刷新中…`（实测 69px，一行合计 238px ✓），把 `12/34 页` 进度移到紧挨其下的 `.tree-meta` 行（那行本来就是「已加载 N 门」的信息位）。

### A2 笔记库「导出 Obsidian」不对齐（观感）

**实锤**

- 结构原因：`.note-library-group-head` 用 `justify-content: space-between`（style.css:1132-1135）且直接子元素有 **3 个**（课程名按钮 / 导出 Obsidian / 升级旧笔记）→ 中间那个由「剩余空间均分」决定位置，**跟随左侧课程名长度漂移**。
- 几何实测（三个分组）：
  | 分组 | 导出 Obsidian 左边缘 | 升级旧笔记 |
  |---|---|---|
  | 斯坦福 CS224N…（长名） | **941** | 1102→1186 |
  | 电子电路及系统I课程设计 · 王辰星 | **775** | 1102→1186 |
  | Python语言设计 · 高旺 | **743** | 1102→1186 |
- 也就是说「升级旧笔记」因为排在最后被钉死在右边（三行完全对齐），而「导出 Obsidian」三行差出 **198px**——正是你看到的不齐。

**修法（推荐 D3-A）**：把两个按钮包进 `.note-library-actions`（`margin-left: auto; flex: none; display: flex; gap: 6px`），**整簇靠右**。两行按钮的左、右边缘都逐一对齐（1186 右 / 996 左），且保留现有语义顺序（导出=次要在前，升级=主要在后、最后一位）。若你要「导出 Obsidian 就在最右」→ 交换两键顺序即可（D3-B）。

## 3. 新功能：课程全屏浏览（铺满全屏 + 搜索 + 筛选）

### 3.1 为什么现在做、解决什么

本地已收录 1654 门课，而侧栏 304px 宽、一次只露 150 门、还要和「我的学习」抢空间——你的原话「侧栏选课效率不够高」。而且**同名课是这个库的常态**（学位英语 212 个教学班、劳动教育与实践 130 个），真正要区分的是**教师 / 教室 / 讲次 / 学期**，这些信息在窄侧栏里全被截断（`（中英...`、`电子电路及系...`）。全屏浏览页把「找课」变成一屏可扫、可搜、可筛的网格。

### 3.2 形态与交互（推荐 D5-A：近全屏模态层）

- **一个近全屏模态卡片**（`width: min(1440px, 98vw); height: 92vh`），沿用 CourseMapDialog 已成为惯例的模态语言：`useModalScrollLock(true)` + `useFocusTrap` + **Esc 关闭** + 背板点击关闭 + 右上「关闭」。理由：与全应用模态一致、随时可退，不改变主界面骨架；同时 98vw × 92vh 事实上就是「铺满全屏」。
  - （备选 D5-B：真全屏替换内容区、隐藏侧栏与页签。更「全屏」，但要新开一套布局态、和侧栏折叠语义打架，故不推荐。）
- **顶部信息条**：标题「全部课程」+ 计数（筛选后 N 门 / 本地已收录 1654 门）+ 一句平台边界说明 + `[刷新课程]`（沿用侧栏同一按钮语义；`logged_out` 时 disabled，`refreshBusy` 时「刷新中…」+ disabled）。
- **工具栏**（一行，窄窗口自动换行）：
  - 搜索框（打开即聚焦；命中 **课程名 / 教师 / 学期 / 教室 / 讲次 / 课程号 / 课程 ID / 课时标题**）
  - `学期` select（实测值只有 2026-2027 与空，两三项）
  - `来源` select（全部 / 校内 / B站）
  - 状态 chips：`全部` `已提取` `已收藏` `有课时目录` `从未处理` `可清理空课`（多选，默认全部）
  - `排序`：默认（收藏 → 已提取 → 课程名）/ 课程名 / 教师 / 最近任务
  - `[清除筛选]`（仅在有筛选时出现）
- **教师维度**：450 个教师不适合塞 select，改为**点卡片上的教师名 = 加一个教师筛选 chip**（chip 可点掉）。搜索框同样能直接打教师名。
- **网格**：`repeat(auto-fill, minmax(300px, 1fr))`。卡片内容：
  - 一行：头像 + 课程名（超长两行截断）+ 徽标（`B站` / `N 课时` / `已提取 M`）
  - 一行：`教师 · 教室 · 讲次 · 学期`（**用既有 `courseSubLine` 同款拼法**，这是区分同名课的关键信息）
  - 一行操作：`收藏(星)` / `课程导图` / `抓取课时目录`（无目录时）/ `删除`（仅从未产生数据的空课，复用 C6 的删除确认 Dialog）
  - **展开课时**：点卡片展开课时列表（`已处理✓` / `未处理` 徽标）；**点课时 = 选中该课时 + 关闭浏览页**，直接落到任务/笔记上下文——这是「几百门课里找到想上的那节」的最短路径。
- **分块渲染**：初始渲染 120 张，底部「显示更多（还有 N 门）」按钮（沿用侧栏既有 chunk 约定，不引入虚拟滚动；1654 门不一次性进 DOM 是 M3-2 已收口的老账）。
- **空结果**：`没有匹配的课程——试试只搜教师名，或清除筛选`（与侧栏同一句话术）。
- **不做**（本批）：多选批量操作、课程分组聚合视图（按同名课折叠成「学位英语 ×212」这类）、课程号搜索结果的语义化展示——列为后续候选。

### 3.3 搜索口径统一（推荐 D7-A）

现在侧栏搜索的 haystack 是 `name teacher term id` + 课时标题（`App.tsx:1523-1542`），**不含教室/讲次/课程号**。全屏浏览页要更宽的口径（否则「博雅楼A-308」搜不到）。两套口径会让用户困惑（同一个词在侧栏与浏览页结果不同），所以：

- 新增纯函数模块 `src/shared/course-search.ts`：`courseMatchesQuery(course, query)`（haystack = 名称/教师/学期/教室/讲次/课程号/subjCode/ID + 课时标题，大小写归一），**侧栏与浏览页共用**。侧栏顺带获得「按教室/讲次/课程号搜」的能力。
- 配 `tests/course-search.test.ts`（纯函数，无 DOM）。

### 3.4 入口（推荐 D6-A：图标按钮 + Ctrl+K）

1. **侧栏「全部课程」行尾的图标按钮**（`Maximize2`，title「全屏浏览全部课程」）：`.all-courses-head` 现在是整行一个大按钮（`width: 100%`），不能嵌套按钮 → 改成 `.all-courses-row`（flex 行：按钮 + 图标按钮），保留 `data-testid="all-courses-toggle"` 与既有 aria 语义，测试选择器不受影响。

## 6. 验收与交付

- 每批：`npm run lint && npm run typecheck && npm test` 全绿；批4 起加 `npm run build`。
- 收尾：`npm run smoke`（CDP 烟测 32/32）+ 隔离库实拍走查（A1-A8 逐项对照「修前/修后」截图证据）。
- **需要你装机走查的**（沿用惯例，我给清单）：
  1. 侧栏头部一行化后，在你 304px 的实际观感里是否舒服；刷新课程进行中（页数进度）是否出现在搜索框下方那行；
  2. 笔记库三行的两个按钮是否严格对齐；空态横幅消失后首屏是否更干净；
  3. **真机点开全屏浏览页**：搜索「电子」「博雅楼」「王辰星」各试一次；点卡片展开课时 → 点一节课时是否直接落到任务页并带上该课时；Ctrl+K 是否顺手；
  4. 失败任务的原因文字是否读得全（两行）。
- 交付形态：不 bump 版本、不打 tag（沿用「先测试构建、你点头再发」的既有节奏），除非你明确要求发布。
