## 0. 结论先说

**「十分钟换来一篇枯燥文字笔记」= 五个独立失效叠加，且每一环都静默：**

| # | 失效 | 机制 | 今天这次的实际后果 |
|---|---|---|---|
| 1 | **模型可能根本没看到图** | 绑定的多模态模型 `mimo-v2.5`（仓库预设，ProviderPanel.tsx:24）**无视觉能力**——图片被网关 400（静默纯文本重发，summarizing 阶段直接翻倍）或悄悄忽略（token 白烧） | 模型从未见过 18 张图 → evidence 引用 0/18 **是必然不是偶然**；之前的「MiMo 引用遵循度弱」归因**不准确，本稿更正** |
| 2 | **B 站视觉断供且静默** | playurl 412 风控 → videoStreamUrl=null → 合法降级 0 帧，全程无一处告知 | 该用户这次有 18 帧（流拿到了），但断供路径本身是同类投诉的高发原因 |
| 3 | **帧密度与发送预算被焊死** | `fps=1/10` 固定 + 去重无覆盖保底 + `MAX_SUMMARIZE_IMAGES=20` 是同一个数字 | 73.8 分钟视频 18 帧，**最后 935 秒（21%）零素材** |
| 4 | **绑图是筛子不是分配器** | 挂图全靠模型自觉 + 90s 最近邻兜底 | 18 张卡只有 **5 张有图（28%）** |
| 5 | **时间戳不核验 + 一根时间线轴 + 文字墙呈现** | `timeline.at` 从不与素材范围比对；无章节/金句/导学；640px 单列无封面无目录 | **5 条时间线（28%）时间戳超出视频本体最多 62 分钟**（编造）；体感「枯燥无味」 |

叠加过程层：**为抽帧而下载整片**（74 分钟 360P，3–8 分钟）占等待的大头；10 分钟硬超时先吞一次 10.5 分钟。

**最刺眼的一个数字**：这篇让用户体感「质量很低」的笔记，当前体检结论是 **good / 0 warn**——检查不到没图、假时间戳、两成时长无素材，于是系统对用户说「良好」。**信任就是这样被消耗的。**

**方案总纲**：批 0 只读取证 → **批 A 视觉供给链救急**（能力匹配、封面、断供恢复、帧库增密、绑定分配器、可见化）→ **批 B 内容结构**（章节/金句/TL;DR 三个可选字段 + 时间戳钳制）→ **批 C 阅读呈现**（封面区、章节分组、图文并排）→ **批 D 原片跳转**（待裁）。超时/分窗/解码阻塞归 09-18 与 audit 两份方案，本稿只衔接不重做。

## 2. 根因分析（五层）

### 2.1 视觉能力层（本稿 v2 新增，证据最强的单一根因）

- 发送端是真多模态（`summarize.ts:170-174` 发 base64 image_url），但**发送不等于收到**：`unsupported_visual` 只在 **400 响应体匹配 `/image|visual|multimodal|vision/i`** 时触发（`openai-client.ts:136-138`），命中后**静默**纯文本重发（`summarize.ts:206-219`）。
- 绑定模型 mimo-v2.5 若无视觉：要么 400 → 整段重发（**summarizing 阶段翻倍，与 10 分钟撞墙直接相关**）；要么网关不报错但忽略图片 → **token 白烧、模型零画面**。
- 两种情况的共同终点：模型没有画面 → 不引 evidence → 全靠兜底。**这是「为什么修了 prompt 遵循度还是 0 引用」的答案：病人没吃药。**
- 横向印证：同库 CS224N/Python 的旧笔记同样 timelineEv≈0，而它们的绑定同样是 mimo 系。

### 2.2 视觉供给层：三个静默断点

1. **封面资产导入即弃**：B 站导入时封面 pic 已解析已下载（`bilibili/parse.ts:64`、`client.ts:175`），只用于导入预览缩略图（`BiliImportDialog.tsx:258`）**后即丢弃**——现成视觉资产白扔；`lessons` 表无封面列。
2. **风控断供合法且静默**：playurl 412 → `videoStreamUrl=null` → `{keyframes:0, skipped:'no-video-stream'}`（`orchestrator.ts:627-630`）→ 笔记合法无证据态，用户侧零可见。
3. **为抽帧下载整片**：字幕快路径跳过 ASR 但不跳过 360P 全片下载（`orchestrator.ts:392-399`→`:631`），74 分钟视频 3–8 分钟就花在这里——「上十分钟」的大头。

### 2.3 视觉密度层：去重杀死无变化时段，密度与预算焊死

- `fps=1/10` 固定（`ffmpeg.ts:145-151`）；`dedupeKeyframes`（`phash.ts:55-63`）顺序贪心去重**无时间覆盖保底**：无画面变化的口播/板书时段 → 第一帧之后全部判重丢弃 → 今天 3490s 后 935 秒零素材。长视频里这是常态（复习/访谈/脱口秀）。
- 抽帧（本地 ffmpeg，边际成本≈0）与发送预算（每张 base64 都是真金白银）**本该是两个决策**，被 `MAX_SUMMARIZE_IMAGES=20` 焊成一个数字。

### 2.4 绑定与呈现层

- 绑定：筛子（90s）而非分配器（§1.2：18↔18 本可全配，实际 5/18）；
- 呈现：首屏纯文字 masthead + md-lite 无图；图集是去重后的近重复幻灯片帧且堆在文末；0 帧时一行灰字。

### 2.5 内容组织层

无章节、无金句、无 TL;DR；`timeline.at` 不核验（今天 5/18 越界 + refStats droppedAt=6 双重实锤）。

### 3.2 合并后的共性配方（八条，两个方案的交集）

1. **截图 + 时间戳锚定是标配**——没有一家把纯文字当合法终态（BiliNote/NoteGPT/JumpVideo）
2. **首屏视觉锚点**——封面 banner / 高光分段卡，第一眼有画面（BiliNote/通义）
3. **章节 + 时间戳**——长内容的第一结构（通义/B 站/Notta）
4. **金句/原话层**——可单独读、单独导出、可划线（Glasp）

6. **预览价值**——总结先回答「值不值得读/看」（Eightify）
7. **多模态能力显式化**——按模型能力切换请求形态，不静默白烧（BiliNote v2.1.3）
8. **可分享成品 / 原片回跳**——文章、信息图、`?t=` 跳转（Eightify/Notta/BiliNote）

**我们的定位**（沿用视觉方案的精准概括并扩展）：五视图结构、证据对齐三层机制、返修门禁、可核验率 100% 这些「内功」领先所有调研对象；差距集中在**视觉资产供给的可靠性、能力匹配、第一眼呈现**——「内功很强、卖相全无」。本稿不发明新能力，只把供给链焊牢、把现有资产用起来、把内容结构补全。

## 5. 批次设计

### 批 0：取证（只读，新增 `scripts/note-visual-audit.ts`）

对真实库每条笔记输出：keyframes 行数 / `extracting_visuals` stage 的 skipped 原因 / capability_bindings 的 multimodal 绑定 / 该笔记的 hitRate 与 refStats。**一分钟回答两个问题**：Andiii 这次断在哪环（本文证据表已给出强假设：流拿到了 18 帧，但绑定模型无视觉）；mimo-v2.5 到底收不收图。**只读，不碰库。** 产出留档 PROGRESS。

### 批 A：视觉供给链（按「性价比 × 依赖性」排序）

**A1 视觉能力匹配**（`orchestrator.ts:710-713` 已有 binding 查询；`summarize.ts` 装载处）
- provider/model 无视觉能力 → `images: []` + 纯文本 prompt，**省一次静默重发的整段时长 + 省 token**；生成 toast/体检明示「当前模型无视觉能力，画面为时间就近对齐」。
- `ProviderPanel` 预设加能力徽标（「无视觉」×3 /「视觉」×1）——在「用户正在做选择的位置」放事实；属功能性标注，不动 DISCLAIMER，spec §5 登记一行。
- 视觉能力怎么判？**不猜**：预设表维护（现成），自定义 provider 保守起见发图（现状）——猜错的代价是不发图丢画面，比白烧轻；BiliNote 的显式开关思路录入 SKILL §15。
- 测试：能力分支、无图时 `buildUserParts` 不含 image part（钉住）、徽标渲染。

**A2 封面资产救回**（migration + 渲染）
- `lessons` 加 `cover_path`（语义独立，不混入抽帧逻辑——视觉方案 D1 推荐 A，本稿赞同）；B 站导入把已下载封面落盘 `attachments/<lessonId>/cover.jpg`；**SEU 源无封面 → 不落，渲染端首帧兜底**。
- 同步两处硬编码（db-migrations 测试、smoke 迁移计数）；导出暂不带封面（导出物纪律「只带实际引用」）。
- 渲染 banner 遵守 ui-layout 纪律（banner 是内容不是装饰，禁彩色边条/限高/低饱和蒙版）。

**A3 B 站断供恢复 + 可见化**
- playurl 412 重试阶梯（降 qn + 间隔重试，参数由批 0 实测定）；失败原因入 stage outputs。
- **字幕快路径免下载抽帧**：有字幕时 `ffmpeg -headers "Referer: …"` 直读流 URL 抽帧（Referer 在下载路径已验证，`orchestrator.ts:282-299`），失败降级回下载后抽帧。**直接砍掉 74 分钟任务里 3–8 分钟的整片下载。**
- **断供可见化**（纪律延伸，必做）：0 帧时任务历史显示「视频流被平台风控拦截，本笔记无画面素材（重试导入可能恢复）」；体检加 **info** 级 findings（无图是合法态，不 warn 不逼编，但用户必须看见原因）；图集空态改说明 + 「重新获取画面」入口（复用 regenerate 的下载-抽帧段，不动模型）。

**A4 帧库增密与发送预算解耦**（依赖 audit 批 3 先行）
- 抽帧 10s → 20s 存全量（74min ≈ 222 帧 ≈ 7MB/课）；**发送预算不变**（仍 ≤20）。
- **覆盖保底**（本稿并入，防去重塌缩）：去重后按时间桶（默认 `clamp(round(duration/120),30,120)`s）补底，空桶取该桶首张候选——即使与已保留判重也补（覆盖优先）。今天这份的最后 935s 会补出约 15 帧。
- 就近池从 20 → 222，配图命中大幅提升；访谈类低变化画面的去重塌缩由覆盖保底兜住。
- audit 批 3（缩略图哈希）被否则自带 worker 化再增密（视觉方案 D7，本稿同荐）。

**A5 绑定分配器**（`evidence.ts` 纯函数）
- 无 evidence 引用时，「时间线条目 × 带时间关键帧」**全局贪心一对一**：所有 (entry, frame) 对按 `|Δat|` 升序、双方空闲即配；每帧至多配一条、每条至多配一帧。
- 容差自适应 `max(2×帧距中位数, 120s)`、上限 600s（超过就诚实文字卡）；caption 展示**帧自身时间**，origin 措辞改「时段对应」。
- 单测：今天这份真实数据的逐条配对回归（帧距中位数 60s → 容差 120s，可配 5 条、帧的归属全局最优）；稀缺帧争用；evidence 不占池；容差封顶 600s；懒加载/已解析两形态一致。
  **诚实口径（2026-09-19 实跑钉住）**：今天这份数据上分配器仍是 5/18——18 帧聚簇在 990–3490s、时间线铺到 7201s，容差内可配的本就那几条；A5 的价值是**归属最优 + 屏幕/PDF 同口径 + 稀疏长视频（帧少但跨度大 → 容差 600s）大幅改善**。覆盖率的跃升靠 **A4**（帧库增密到 20s/222 帧后，容差内基本全配上）。

**A6 图集折叠**：图集按 phash ≤5 折叠成组（「N 张近重复」），默认代表帧、可展开。manifest 增 `hash` 字段 = IPC 契约变更 → **必跑 smoke**。
