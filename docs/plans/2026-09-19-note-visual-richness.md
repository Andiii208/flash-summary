## 0. 结论先说

### 0.1 一句话结论

「全文字无图」不是渲染坏了，而是**视觉素材供给链在 B 站源上存在一条全静默的断供路径**：playurl 风控拿不到流 → 合法降级零帧 → 零证据 → 渲染端无图可配，全程没有一处告诉用户「为什么没图」。叠加第二个因素——**预设模型 4 个里 3 个没有视觉能力，图片静默白烧或触发整次重发**——以及第三个因素——**首屏与图集的呈现把「无图」放大成「枯燥」**。

三个因素各自独立可修，修任何一个都能立刻改善这次的体验；全修才能把「图文并茂」变成默认态而不是侥幸态。

### 0.2 「没有任何视频截图」的完整原因链（B 站源）

```
① 导入      ipc.ts:391-411          只落 bvid/cid/page；封面 pic 已解析已下载（parse.ts:64、client.ts:175）
                                     却只用于导入预览缩略图（BiliImportDialog.tsx:258）后即丢弃——现成视觉资产白白扔掉
② fetching  bilibili/pipeline.ts:96-108  playurl 412 风控（client.ts:120）→ videoStreamUrl = null
                                     长视频是 412 高发对象；字幕命中快路径（client.ts:153-160）→ 字幕直插
③ 下载      orchestrator.ts:392-399 无流地址+有字幕 → recordStage({bilibili:true}) 直接 ok
                                     注释原文「the note proceeds without keyframes (legal evidence-less state)」
④ 抽帧      orchestrator.ts:627-630 {keyframes:0, ppt:0, skipped:'no-video-stream'} → keyframes 表零行
⑤ summarize summarize.ts:96-144     images=[]、allRefs=∅ → buildUserParts 纯文本（:165-179）
                                     prompt 禁止编造 ref（:46,63）→ 模型无 ref 可引，编了也会被
                                     normalizeEvidence（schema.ts:190-204）+ dropUnknownEvidence（evidence.ts:195-211）删光
⑥ 渲染      attachments.ts:21-32   manifest 空 → bindTimelineImagesLazy 无 ref 无就近帧（evidence.ts:103-122）
                                     → 时间线卡片无图（NoteBlocks.tsx:268）、
                                       图集只剩一行「本课时尚无可用画面素材」（NoteBlocks.tsx:334）
```

每一环都是**静默降级不报错**——「降级而非报错」纪律（note-craft §0）本身没错，错在**降级后用户侧零可见性**：体检照常可评 good（画面缺失不进 findings）、任务历史只显示成功、图集空态是一行灰字。这与 2026-09-18 笔记库方案确立的「不静默截断」纪律是同一个缺口在视觉通道上的复发。

### 0.3 三个叠加因素（即使流没断也存在）

**① 预设模型 3/4 无视觉，图片白烧或双倍耗时。**
发送端是真多模态（`summarize.ts:170-174` 发 base64 `image_url` part），但预设模型 deepseek-chat / Qwen2.5-7B / mimo-v2.5 都没有视觉输入能力（ProviderPanel.tsx:21-25）。命中 `unsupported_visual`（openai-client.ts:136-138，仅当 400 响应体匹配 `/image|visual|multimodal|vision/i`）时**静默**以无图 prompt 重发一次（summarize.ts:206-219）——对 74 分钟视频意味着 summarizing 阶段直接翻倍（单次已实测 601s 撞墙，见 09-18 方案）；若网关不返回 400 而是悄悄忽略图片，则是**纯烧 token 买零信息**。且模型从未「看过」任何画面 → evidence 产出近乎为零 → 即使 keyframes 表有图，时间线也只能靠 ±90s 就近配图兜底。

**② 帧密度：74 分钟视频只有 20 帧，且抽帧密度与发送预算被焊死在一起。**
`fps=1/10` 均匀采样（ffmpeg.ts:145-151，无场景检测）→ 74min ≈ 444 候选 → 去重后受 `MAX_SUMMARIZE_IMAGES = 20` 硬预算（summarize.ts:28）→ 实际入库与发送都是 20 帧 ≈ **每 3.7 分钟一帧**。±90s 就近配图在这个密度下大量落空；访谈类画面变化少、哈希去重后更稀。**抽帧（本地 ffmpeg 扫一遍，边际成本≈0）和发送预算（每张 base64 都是真金白银）本该是两个决策**，现在被焊成同一个数字。

**③ 呈现：首屏无任何图，「无图」被放大成「枯燥」。**
详细视图首屏 = masthead 纯文字 + 概览 markdown（views.ts:139-150、NoteViewer.tsx:331-338）；md-lite 无图片语法（md-lite.ts:8-15）；「课堂画面」空态只有一行灰字。即使有 20 帧，用户第一眼看到的仍是纯文字墙——B 站封面这个现成资产在导入后就丢了，首屏视觉锚点从未存在过。

### 0.4 「上十分钟」的构成（为什么慢）

B 站源无阶段计时埋点（grep `elapsed/耗时` 零命中），按参数推算 74 分钟视频：下载 360P 全片**只为抽帧**（字幕快路径跳过 ASR 但不跳过下载，orchestrator.ts:489-499 → 631）+ ffmpeg 全片扫描 + summarizing 单次大请求（全量转写 + ≤20 图，600s 超时）+ 可能的 unsupported_visual 重发或返修第二次请求。**本方案批 2 砍掉下载大头，批 3 砍掉重发；分窗/预算守卫归 09-18 方案批 1/批 4，不重复。**

## 1. 外部调研：优秀产品怎么解决「视频笔记枯燥」

### 1.1 调研对象与来源

| 产品 | 形态 | 关键做法 | 来源 |
|---|---|---|---|

### 1.2 共性配方（四条，按出现频率排序）

1. **截图 + 时间戳锚定是标配**——没有一家把「纯文字」当合法终态；截图让笔记「可回看」，是「值得总结」的直观证明。
2. **首屏视觉锚点**（封面 banner / 高光分段卡）——打开笔记第一眼有画面，价值感立刻建立。
3. **多模态能力显式化**——按模型能力切换请求形态或提供开关，而不是静默白烧。
4. **原片跳转**——时间戳点击回原视频，把笔记变成「索引」而非「替代品」。（本仓对 SEU 源已裁定不做：平台播放页无时间参数，note-craft §12；B 站源存在公开的 `?t=` 机制，列为 D5 待裁。）

**本仓的差距定位**：五视图结构、证据对齐、返修门禁这些「内功」领先于所有调研对象（BiliNote 就是一段 markdown + 截图，无体检无返修）；差距集中在**视觉资产供给的可靠性**与**第一眼呈现**——即「内功很强、卖相全无」。所以本方案不发明新能力，只把供给链焊牢、把现有资产用起来。

## 2. 方案批次

原则：延续「降级而非报错」，但**每一次降级必须用户可见**（「不静默截断」纪律延伸到视觉通道）。批批独立可发、四门禁全绿、测试数只增不减。

### 批 0：取证——确认这次断在哪一环（只读，1 个探针）

仿 `note-ref-audit.ts` 写只读脚本 `scripts/note-visual-audit.ts`：对真实库每条笔记输出「keyframes 表行数 / task_stage_outputs 的 extracting_visuals 结果（skipped 原因）/ capability_bindings 的 multimodal 绑定 / 当前 provider 模型」。一分钟内确认 Andiii 这次是 ①-⑥ 哪环断了，为批 2 的 412 重试策略提供实测依据。**只读，不碰库。**

### 批 1：首屏视觉锚点——封面进笔记（成本最低、感知最强）

- **持久化**：lessons 表加 `cover_path` 列（migration + 两处硬编码同步：db-migrations 测试、smoke 迁移计数）。B 站导入时把已下载的封面 base64 落盘到 `attachments/<lessonId>/cover.jpg`；**SEU 源无封面 → 不落，渲染端用第一张关键帧兜底**（屏幕流首帧通常是标题页）。
- **渲染**：详细视图 masthead 加 banner（克制：圆角、限高、低饱和蒙版下压标题——遵守 ui-layout SKILL 刻度与视觉纪律 §7「禁彩色边条/装饰」，banner 是内容不是装饰）；masthead 来源行补「B 站 · UP 主 · 时长」（UP 主 parse 时已在响应里，顺带落库）。
- **导出**：PDF 封面页可复用；Obsidian/Anki **不带**（D7 推荐：导出物只带笔记实际引用的附件，封面是新语义，先应用内）。
- 测试：migration 测试、投影测试（banner 块）、NoteViewer 渲染测试、`ui-shots` 走查截图。

### 批 2：B 站视觉断供恢复——把「合法无证据态」变成「尽量有图态」

- **2a playurl 412 重试阶梯**：降 qn 重试（如 64→32→16）+ 间隔重试 + 失败原因记入 stage outputs。纯工程，实测驱动（批 0 证据决定参数）。
- **2b 字幕快路径免下载抽帧**：有字幕时不再为抽帧下载整片，`ffmpeg -headers "Referer: ..."` 直读流 URL `fps=1/N` 抽帧（B 站防盗链 Referer 已在下载路径验证过，orchestrator.ts:282-299）。失败（URL 时效/风控）→ 降级回「下载后抽帧」旧路径。收益：砍掉 74 分钟任务里 3-8 分钟的整片下载与落盘，且绕开「下载中断从 fetching_course 重来」。
- **2c 断供可见化**（纪律延伸，必须做）：`skipped:'no-video-stream'` 时——任务历史显示「视频流被平台风控拦截，本笔记无画面素材（重试导入可能恢复）」；体检 findings 加 **info** 级「画面素材缺失及原因」（info 不是 warn：无图是合法态，不该逼模型编图，但用户必须看见原因）；图集空态从一行灰字改为说明 + 「重新获取画面」入口（复用 regenerate 的下载-抽帧段，不动模型）。
- 测试：pipeline 风控重试（vi.mock fetch）、orchestrator 空流路径的新 stage 记录、体检 info 断言、文案钉住。

### 批 3：视觉能力匹配——让每一张图的花费都有效

- **无视觉模型 → 不发图**：summarize 装载时查 `capability_bindings` 的 multimodal 能力（已有表，orchestrator.ts:710-713）；无视觉则 `images: []` + 纯文本 prompt（省 token、省一次 unsupported_visual 重发的整段时长），生成 toast/体检明示「当前模型无视觉能力，画面为时间就近对齐」。
- **有视觉模型 → 现状发图**；预算自适应（按分钟提额）归 09-18 方案，本批不动 `MAX_SUMMARIZE_IMAGES`。
- **ProviderPanel 预设标注**：四个预设加能力徽标（「无视觉」×3 /「视觉」×1）——在「用户正在做选择的位置」放事实，遵守声明层纪律（功能性状态标注，不新增承诺，无需动 DISCLAIMER；spec §5 登记一行）。
- 测试：能力判定分支、无图 prompt 形状（钉住：无视觉时 buildUserParts 不含 image part）、徽标渲染。

### 批 4：帧库增密与就近配图——抽帧密度与发送预算解耦

- **抽帧密度 10s → 20s 存全量**（D3）：本地帧库 74min ≈ 222 帧（约 7MB/课，`q:v 2` JPEG）；**发送预算不变**（仍 ≤20 张给模型）；渲染端 `nearestFromManifest` 的就近池从 20 帧变 222 帧，时间线卡片配图命中率与准确度大幅提升，图集也真正「有画面可看」。
- **依赖声明**：哈希解码是同步 jpeg-js 全分辨率解码，增密会放大主进程冻结——**本批必须在 09-19 audit 方案批 3（worker 化）之后落地**；若那份方案被否，本批先自带 worker 化再增密（二选一，Andiii 裁）。
- 测试：抽帧参数、去重阈值在 222 帧下的表现（访谈类低变化画面的去重塌缩验证）、就近配图命中率探针（`ui-probe` 扩展一个模式）、附件 manifest 分页/性能。

### 批 5：B 站原片跳转（D5 待裁，独立小批）

- 无参 IPC `lessons:openSource(lessonId)`：main 侧从库内取 bvid 拼固定格式 `https://www.bilibili.com/video/<bvid>?t=<秒>` 用 `shell.openExternal` 打开——**不渲染层传 URL，红线不破**；时间戳取时间线卡片/图集帧的 `at`。SEU 源不做（§12 维持：平台播放页无时间参数）。
- 落 spec §5 一行 + DISCLAIMER 不动（功能入口，非承诺）。

## 5. 明确不做

- 弹幕高能点/热词（新 API + 风控面 + 范围蔓延，收益不确定——将来单独立项）。
- md-lite 图片语法（模型会编 URL；块层插图已覆盖所有合法挂图点）。
- 场景切换检测抽帧（libsceneclass 滤镜全片扫描更慢，均匀采样+去重够用）。
- 转写预算/分窗/超时治理（09-18 方案领地）；quiz 与一切教学功能（§13 冻结）；自动上报任何数据（红线）。
