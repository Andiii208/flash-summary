## 一、北极星与原则

**北极星：把笔记从「能看」推进到「能考」**——补全学习闭环的记录 → 理解 → **自测 → 记忆** 后半段（Cornell 5R 的 Review 环节，SKILL §9 映射）。

原则（全程有效）：
1. 每批次独立提交、独立验收，四门禁 + smoke + 真实数据 e2e（note-craft SKILL §7 纪律）。
2. 改变产品边界的决定逐批问用户（AGENTS 纪律）；纯实现细节选更简单方案并记录 PROGRESS。
3. 零依赖偏好；新数据字段必须走 note-craft SKILL §0 数据契约流程（schema + 归一层 + 两投影 + markdown 导出 + PrintHandout + 测试六处同步）。

## 三、Phase 1：数据精度与可观测（短期，约 2-2.5 天）

### 批次 1.1 ASR 网关时间戳能力探测（半天，只读）

- **动机**：120 秒分片粒度是全部时间相关功能的精度天花板——timeline 引用、就近配图 90s 容差、QA 时间点引用都受制于此（note-craft SKILL §8 第一条边界）。
- **做法**：活体探测脚本（复用 smoke/probe 模式，独立 userData + 真实会话）：取一段已知内容的真实音频，分别尝试 `response_format: verbose_json`、`timestamp_granularities[]`、segment 级返回结构；记录网关是支持、拒绝还是静默忽略。
- **产出**：`docs/health/2026-09-XX-asr-timestamp-probe.md` 探测报告（含原始响应样例）。
- **验收**：报告给出明确的「支持/不支持」结论；产品代码零改动。

### 批次 1.2 转写分段级时间戳（条件批次：1.1 结论支持才启动，约 1 天）

- **改动面**：`makeTranscribe` 解析 segment 级时间戳。`segments_json` 的 `{at, text}` 结构**不变**，只是 `at` 从分片起点变为真实偏移——下游（schema/views/evidence/qa）零改动，这是当初数据结构设计的红利。
- **联动收紧**：就近配图容差 `NEAREST_SECONDS` 90 → 30（evidence.ts 单常量 + 测试同步）。
- **验收**：真实课时重转写，segments `at` 单调递增且与语音内容对齐（抽样人工核对 3 段）；管线 e2e 绿；测试数只增。
- **风险与兜底**：网关不支持 → 本批次取消，维持现状（三层对齐已验证可用）；旧转写无需迁移（重新生成时自然覆盖）。

### 批次 1.3 证据引用命中率度量（半天）

- **做法**：`regenerate` 返回值增加 `hitRate`（timeline evidence 中 ref 精确命中附件的比例，纯函数放 evidence.ts）；UI 在重新生成 toast 与笔记工具栏显示「引用命中 12/17」。
- **阈值动作**：命中率 < 60%（G0-2 或后续观测）→ 追加小批次 1.3b：system prompt 加一个 few-shot 完整示例（含正确 evidence 用法），或将 summarize 拆两阶段（先时间线后强制配图）——届时按命中率数据选更简单者。
- **验收**：真实重新生成显示命中率；计算函数单测（全命中/部分/全不中三例）。

## 四、Phase 2：学习价值延伸（约 2.5-3.5 天）

### 批次 2.1 Quiz 自测题（1-1.5 天）——★本 Phase 核心

- **数据契约**：`NoteSchema` 增 `quiz: [{question, answer, source: 'concept'|'examCue', term?}]`。六处同步：schema+zod 归一、views 投影（要点视图新「自测题」块）、markdown 导出、PrintHandout（题面+答案分栏）、组件、测试。旧笔记无 quiz 字段 → default `[]`，零迁移。
- **生成**：并入 summarize 同轮 prompt（一次调用同时产出，避免二次调用成本）；要求每题必须锚定一个概念或考点（`term`/来源），禁止无锚题。
- **交互**：先显示问题 → 点击翻面显示答案（Preact 状态翻转，无新依赖）；quiz 为空则整个块省略（SKILL 空 section 纪律）。
- **理论依据**：Cornell Cue 栏的自测钩子 + qiaomu（5.9k★）输出形态调研（SKILL §9）。
- **决策 D1（已拍板 2026-09-04，全按推荐）**：题型默认**问答翻转**（最简单）；选择题/填空题留待实测反馈。
- **验收**：契约/投影/组件/导出四层测试 + 真实数据重新生成出题 ≥5 题。

### 批次 2.2 Anki 导出（0.5-1 天）

- **决策 D2（已拍板 2026-09-04，全按推荐）**：**TSV/CSV**（Anki 原生可导入，零新依赖，复用 markdown 导出的 dialog/writeFile/reveal 管线）；`.apkg` 不做（需 genanki 类库，违背零依赖偏好）。
- **内容**：概念卡（term → definition）+ Quiz 题（question → answer）各一张牌堆，附来源课时列；无 quiz/概念时对应堆跳过。
- **验收**：真实笔记导出 → 用户在 Anki 导入成功（人工一步）；导出文件名走 safeFileName。

### 批次 2.3 PDF v2 打磨（条件批次：G0-3 驱动）

- 体积敏感 → 关键帧嵌入前降采样（jpeg-js 已在依赖内可复用解码；限制最长边 ≤1280px 重编码，预估 4.2MB → ~1.5MB）。
- 分页敏感 → 目录页（板块锚点，不带页码——printToPDF 无两遍布局拿不到精确页码，记录取舍）。
- 未排工作量，按信号启动。

## 七、风险与对策

| 风险 | 对策 |
|---|---|
| MiMo 网关不支持时间戳 | 1.2 取消，接受 120s 粒度——三层对齐已验证可用，不阻塞任何其他批次 |
| LLM 出题质量差（超纲/答案含糊） | quiz 契约允许空数组优雅降级；prompt 要求逐题锚定概念；实测迭代 |
| Quiz/课程级导致 prompt 膨胀、总结质量被稀释 | Quiz 并入同轮但置于 JSON 末位字段；若实测概述质量下降，回退为二次调用生成 |
| 课程级聚合性能 | 概念合并走 DB 聚合查询（courseTree JOIN 已有先例）；渲染端复用 150 门增量渲染模式 |
| IPC 大 payload 增长（课程级） | 沿用现有 data URL 管线与 8MB/张上限；课程级只传聚合 JSON 不传图 |
