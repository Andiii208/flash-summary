## 一、问题定义：「单一」到底是什么

现状能力清单（代码事实，2026-09-05 复核）：

- **数据**：`TreeNode = { title, children }`（`src/shared/notes/schema.ts:67`）——纯标题树。节点不携带任何内容锚：与 concepts/quiz/timeline/证据**零关联**，路径是位置索引（`0/1/2`）而非稳定 ID。
- **布局**：`mindmap-layout.ts` 纯函数——左根向右、贝塞尔连线、CJK 宽度估算、多行换行（行首禁则）、折叠路径集、per-node 高度。屏幕版（MindMap.tsx）与 PDF 静态版（PrintHandout）共用同一几何（架构铁律，「明确不做」清单钉住不换库）。
- **交互**：点击折叠（常驻 caret + 折叠后代计数胶囊）、Enter/Space 键盘切换、FLIP 平滑过渡、层级配色描边。仅此而已。**无缩放、无拖拽平移（只有原生滚动条）、无搜索、无下钻、无内容联动、无导图单独导出**。
- **生成端**：SYSTEM_PROMPT 对 `knowledgeTree` **零质量约束**（`src/main/notes/summarize.ts:27`）——要求 1)-5) 全是 at/证据/overview/quiz 的规矩，树没有层数、分支数、粒度、覆盖面的任何要求。实测真实笔记树 19 节点。「单一」的一半来自生成端放任。
- **导出**：整册 markdown 导出已含「知识结构」缩进大纲（`markdown.ts:5` treeLines）——大纲导出已存在，不缺。

「单一」的三层含义（本计划逐一回应）：

1. **交互单一**——只能折叠，大树看不全、找不到、出不去；
2. **信息单一**——导图是孤岛，节点与概念定义、自测题、考点互不相通；
3. **场景单一**——只有单课时视图，复习期最高频的问题「这门课学了什么」没有导图形态的答案。

## 二、北极星与原则

**北极星：把导图从「课时结构的静态挂图」升级为「学习导航 + 自测骨架」**——服务「记录 → 理解 → 自测 → 记忆」闭环的后半段（与笔记演进 2.1 Quiz 同向，且比 Quiz 更依赖结构）。

原则（全程有效）：

1. **零依赖**：自绘 SVG 不动摇；渲染器只做变换（缩放/平移是 CSS transform，不进布局函数）。
2. **几何单一事实源**：任何布局改动必须留在 `mindmap-layout.ts` 纯函数内，屏幕与 PDF 自动共享；纯渲染器功能（缩放/搜索/遮罩）不得触碰几何。
3. **数据契约六处同步**：schema + 归一层 + 两投影 + markdown 导出 + PrintHandout + 测试（note-craft SKILL §0）；新字段一律可选带默认值，旧笔记零迁移、功能优雅降级。
4. **锚定纪律沿用 quiz 先例**：term/标题原样精确匹配，解析失败即在归一层丢弃，绝不渲染死链（evidence 三层机制的树版翻版）。
5. **学习科学依据优先**：提取练习 > 被动看图（见调研），能承载「回忆」的功能权重高于纯视觉花样。

## 三、调研结论（2026-09-05 网络调研）

1. **交互基线**：markmap（拖拽平移 + 滚轮缩放 + 折叠）、NotebookLM（分支下钻 + 缩放）、Xmind（关系线/边界/概要/多结构/演示模式）——pan/zoom/collapse 是三产品标配，本产品只有 collapse，全面落后于基线。
2. **学习科学**：Karpicke & Blunt（*Science*, 2011）——提取练习的学习增益显著优于「精心制作式」的概念图学习；从记忆中重建结构（retrieval mapping，Learning Scientists）同时吃到提取与结构两份收益；RetrievalPractice.org 的实操建议——把图当**提取工具**用（先回忆再揭示），且重视「关系」而非「节点」。→「回忆模式」有直接依据，且是本产品的差异化功能。
3. **NotebookLM 的高频抱怨是「不可编辑」**——但社区接受它仍是标杆，因为定位是理解材料而非创作工具。本产品同定位：不做编辑器（记入明确不做）。

## 五、批次计划

### Phase M1「先让树值得看」（约 2 天，立竿见影）

#### 批次 M1.1 生成端树质量约束（0.5 天）

- **动机**：SYSTEM_PROMPT 对 knowledgeTree 零约束——层数、分支数、粒度全凭模型发挥，第一层粒度不均、深浅失控。
- **做法**：prompt 追加第 6) 条：根 = 课时标题；第一层 3-6 个主分支（对应本讲主要板块）；整体 3-4 层；节点标题为名词短语（概念/主题）≤ 20 字；叶子承载细节；覆盖全课不遗漏主板块。
- **验收**：真实 1690625-L0 重新生成——树 3-4 层、第一层 3-6 分支；四门禁绿（prompt 无新测试面，schema 归一回归即可）。
- **风险与兜底**：模型遵循度差 → M1.1b 加 few-shot 完整树示例（1.3b 同款先例）。

#### 批次 M1.2 导图工具栏：搜索高亮 + 层级控制（1 天）

- **做法**（纯渲染器）：MindMap 视图内顶部加导图专属子工具栏（复用 `.btn.small` 样式）：
  - 层级控制：「展开到 L1 / L2 / L3」「全部展开」「全部收起」——折叠集 = {有子代且 depth ≥ N 的路径}（「全部收起」即展开到 L1），纯集合运算，复用现有折叠机制与 FLIP；
  - 搜索框：标题大小写不敏感子串匹配 → 命中节点高亮描边 + 自动展开命中路径 + 非命中降透明度 + **自动滚动定位到首个命中节点**（找到但看不见等于没找到）；清空即恢复。搜索展开直接写回折叠状态、不做快照还原——更简单方案，记取舍。
- **验收**：组件测试（高亮类名/展开集合计算/清空恢复）+ 真实库 `ui-shots` 截图 + 四门禁。
- **决策点 D1**：工具栏位置 = 导图视图内子工具栏（推荐，不污染其他视图）vs NoteViewer 全局工具栏。

#### 批次 M1.3 缩放 + 拖拽平移（1 天）

- **做法**（纯渲染器，几何零改动）：Ctrl+滚轮缩放（0.4x–3x，以指针为锚点）、无修饰滚轮保持原生滚动、按住空白处拖拽平移、「重置视图」按钮、键盘 `+`/`-`/`0`。实现路径批次内定：**SVG viewBox/transform 优先**——PrintHandout 已有 viewBox 缩放先例（`PrintHandout.tsx:184`），且天然配合现有 `.mindmap-scroll` 滚动容器；CSS scale 方案有 transform 不影响滚动布局尺寸的坑（自查修订：原稿绑死 CSS transform 是过早约束）。
- **约束**：`mindmap-layout.ts` 一行不改；PDF 静态版不受影响。
- **验收**：组件测试（档位/复位）+ CDP 探针验证缩放变换与滚轮事件 + 真实库双主题截图 + 四门禁。
- **风险**：手势冲突——Ctrl 优先缩放、拖拽与文本选择用 `user-select:none`（markmap 同策略）。

### Phase M2「让导图连着内容」（约 3-3.5 天，本计划核心）

#### 批次 M2.1 数据契约：TreeNode 内容锚定（1 天）

- **契约扩展**：`TreeNode` 增可选 `terms?: string[]`——该节点分支涉及的概念，原样引用 `concepts[].term`。锚定纪律 = quiz 先例：归一层按 concepts term 集合精确校验，解析不了的丢弃，不报错不渲染死链。
- **六处同步**：schema/zod、归一层（新增 normalizeTreeTerms）、views 投影、markdown 导出（大纲行内注记 `（概念：X、Y）`）、PrintHandout（节点副行小字，可关）、组件、测试。**几何注意（自查补）**：屏幕版 terms 只进 ℹ️ 浮层（overlay，不碰布局）；但 PDF 版「副行小字」会改变节点高度——`nodeHeight` 需加可选副行高度参数（原则 2 允许的布局函数内改动），缺省不变以保证旧调用方（含 M4.1 课程图）行为零变化。
- **生成端**：prompt 树质量条款追加「knowledgeTree 节点可带 terms 数组，原样引用 concepts 的 term」。
- **已知风险（前向引用，自查补）**：JSON 里 knowledgeTree 位于 concepts **之前**——模型写树时尚未见概念表，terms 遵循度存疑（1.3 证据命中率 0/8 的同型教训）。验收探针命中率 <60% → few-shot 完整示例或两阶段生成（1.3b 同款后备）。
- **旧笔记**：字段缺省 `[]`，零迁移；无锚节点在 M2.2 诚实隐藏浮层入口。
- **验收**：归一测试（合法保留/非法丢弃/整体缺省）+ 真实重新生成 terms 命中率探针 + 四门禁。

#### 批次 M2.2 节点信息浮层 + 一键跳转（1-1.5 天）

- **做法**：节点内新增 ℹ️ 小圆钮（不占折叠热区）→ 浮层卡：关联概念（term + 定义）、锚定该概念的自测题（问题默认遮住，点击翻面——复用 QuizCards 交互）、按钮「在详细笔记中查看」→ 切回 detailed 视图并滚动至对应概念卡。「滚动至概念卡」需要给概念卡加锚点机制（卡 id + scrollIntoView）——当前视图无锚点，这是本批实现里最大的一块新成本（自查提示，勿低估）。
- **交互分工**：节点主体点击 = 折叠（现状不变）；ℹ️ 钮 = 浮层。两热区物理分离，不打架。
- **验收**：组件测试（浮层渲染/空锚隐藏/跳转回调）+ 真实数据双主题截图 + 四门禁。
- **决策点 D2**：主体点击仍折叠 + ℹ️ 钮浮层（推荐，改动最小）vs 主体点击浮层 + caret 折叠（NotebookLM 式，迁移成本高）。

#### 批次 M2.3 回忆模式——自测骨架（1 天）★差异化功能

- **依据**：Karpicke & Blunt（Science 2011）——先凭记忆重建再对照，优于被动看图；本产品「能考」北极星在导图上的直接落点。
- **做法**（纯渲染器）：工具栏「回忆模式」开关——开启后 depth ≥ 2 的节点标题遮罩（同底色色块覆盖，宽高不变零抖动），逐个点击揭示；「全部揭示」一键复位；顶部一句提示「先回忆再揭示：凭记忆说出这个分支讲过什么」；退出模式全恢复。与 M2.2 浮层联动：揭示后 ℹ️ 可看概念与自测题，形成「结构回忆 → 内容自测」的完整链。
- **边界**：不进 PDF（屏幕自测语义）；不改布局几何；**与搜索互斥**（自查补：遮罩态下搜索自相矛盾——一边遮标题一边点亮标题；进入回忆模式清空搜索，工具栏 UI 上体现为单选开关组）。
- **验收**：组件测试（遮罩类名/揭示集合/退出恢复/与搜索互斥）+ 真实数据双主题截图与人工试玩 + 四门禁。
- **决策点 D3**：揭示粒度 = 逐节点（推荐）vs 逐分支（一次揭整枝）。

### Phase M3「结构增强」（约 3 天）

#### 批次 M3.1 跨节点关联线（1-1.5 天）

- **动机**：概念间的「前提/对比/易混淆」关系是单亲树表达不了的；Xmind 用 relationship line 验证过该语义的学习价值；学习科学同样强调「关系」优先。
- **契约扩展**：`NoteSchema` 增可选 `conceptLinks?: [{from, to, label?}]`——from/to 为概念 term 或节点标题（解析：先 term 后标题，均精确匹配；多命中取首个；解析失败整条丢弃，归一层处理）。prompt 追加「概念间有强关联时输出 conceptLinks，最多 5 条，label ≤ 4 字（前提/对比/易混）」。
- **布局**：`mindmap-layout.ts` 增可选 `links` 入参（缺省 []）——解析为节点 id 对，输出虚线贝塞尔 + label 小标签；视觉纪律：低饱和虚线，与主边明显分层。**端点被折叠时该线不渲染**（最简方案，记取舍；升级为「画到最近可见祖先」留待实测反馈）；label 归一层超长截断丢弃（同 ref 纪律）。
- **验收**：布局纯函数直测（有链/无链/解析失败/端点折叠不渲染）+ 归一丢弃测试 + PrintHandout 调用点同步与 PDF e2e 回归（D4 若含则必验，layout 签名变了）+ 双主题真实截图 + 四门禁。
- **决策点 D4**：PDF 是否含关联线 → 推荐含（几何同源，实现即共享）。

#### 批次 M3.2 焦点模式——分支下钻（1 天）

- **做法**：双击有子代节点 → 以该子树为根重新布局（同一布局函数传 subtree）+ 顶部面包屑「全图 / 分支A / 分支B」逐级返回。NotebookLM 已验证的交互。
- **实现要点**：焦点路径存 renderer state；布局入参 = 从 tree 沿路径下钻取子树；折叠集在下钻/返回时按前缀语义保持。
- **验收**：组件测试（下钻/面包屑/折叠集语义）+ 截图 + 四门禁。
- **决策点 D5**：下钻手势 = 双击（推荐，与单击折叠不冲突）vs 长按。

#### 批次 M3.3 导图单独导出：SVG（0.5-1 天）

- **做法**：导图工具栏加「导出 SVG」——序列化屏幕 SVG（内联节点/连线必要样式 + 字体回退声明；**强制纸白色板**——参照 PrintHandout 硬编码色先例 `PrintHandout.tsx:194` 与 SKILL §6 打印纸白纪律，暗色主题下导出仍是白底），复用 notes:exportMarkdown 的 dialog/writeFile/revealFile 管线。新 IPC 通道 `notes:exportSvg` 按 SKILL §7 落 FakeIpc 测试样板 + smoke 桥面登记。整册 markdown 大纲导出已存在（`markdown.ts` treeLines），不重复做。
- **验收**：导出函数直测 + 真实数据产物浏览器打开验证 + 四门禁。
- **决策点 D6**：格式 = SVG（推荐，矢量 + 实现小）vs PNG vs 两者都做。

### Phase M4「课程级」（约 2 天，每批单独批准）

#### 批次 M4.1 课程总导图（2 天，含新 IPC 通道与 smoke 登记）

- **动机**：「这门课学了什么」是复习期最高频的问题。各课 knowledgeTree 已全量落库，聚合零新模型调用。
- **数据通道（自查补，原稿缺口）**：`notes:list` 只返回索引信息不含树（`src/main/ipc.ts:826` 实锤）——需新 IPC `notes:courseTree(courseId)`：main 侧一次查询聚合该课程全部课时的最新版树；按 SKILL §7 落 FakeIpc 测试样板 + smoke 桥面登记。「第 N 节」课序解析复用 `src/shared/course-order.ts` 现有函数（A4 批次已 shared 化，不复制第二份）。
- **做法**：纯函数 `mergeCourseTree(entries: {lessonTitle, tree}[]): TreeNode`（放 src/shared/notes/）——根 = 课程名，第一层 = 课时（按「第 N 节」课序），子树 = 该课树。入口：课程树课程卡「课程导图」按钮 → 复用 MindMap 全部交互（默认折叠到第 1 层；M1.2 层级控制 + M3.2 焦点模式正是为撑住大图而设）。
- **边界**：只聚合展示，不引入跨课时概念链接（QA 课时纪律不破）；不进 PDF（讲义是单课时语义）。
- **性能**：布局函数对折叠子树本就不展开测量（现状红利）；默认折叠下 30 课时 × ~20 节点无压力，展开性能届时实测。
- **验收**：聚合纯函数直测（课序/空树跳过）+ 真实课程 e2e 截图 + 四门禁。
- **决策点 D7**：入口 = 课程树课程卡按钮（推荐）vs 笔记库筛选视图。

## 七、明确不做（本计划承诺）

- **不换导图库**（重申 2026-09-05 既有决定）——自绘 SVG 是 PDF 共用几何根基。
- **不做导图在线编辑器**——定位 = 复习材料生成器；NotebookLM 同样不可编辑仍是标杆。
- **不做力导向概念图 / 鱼骨图 / 矩阵图 / 流程图等新结构**——关联线已承载概念关系语义；时间线视图承载时序、方法论视图承载步骤，重复建设。
- **不做演示/Pitch 模式**。
- **不做跨课时概念链接与课程级概念图谱**——课时边界纪律（与 QA 同源）；课程总导图只是聚合展示。
- **回忆模式不进 PDF**。

## 八、风险与护栏

- **模型遵循度**（树质量 / terms / conceptLinks）→ 归一层丢弃非法项 + 真实数据命中率探针 + few-shot 后备（1.3b 先例）；terms 另有前向引用风险（见 M2.1）。
- **大树性能**（课程级）→ 默认折叠 + 焦点模式；布局只测展开部分是现状红利，异常再谈虚拟化。
- **手势冲突**（拖拽 vs 选择、Ctrl 滚轮 vs 滚动）→ markmap 同策略 + CDP 探针实测。
- **真实重生成的网络前置（自查补）**：Clash TUN 开着会挂大请求（PROGRESS 实锤）——执行 M1.1/M2.1 真实验证前先确认网络环境。
- **双主题（自查补）**：改渲染的每批验收统一含双主题截图（ui-shots --light/--dark）。
- **批次依赖（自查补）**：M2.2←M2.1（terms）；M2.3 浮层联动←M2.2；M4.1←M1.2+M3.2（大图可撑）；M1.2/M1.3 相互独立可并行。
- **测试纪律**：每批四门禁 `npm run lint && npm run typecheck && npm test` + `npm run smoke` + 真实数据 e2e（note-craft SKILL §7）；测试数只增不减；改契约必落钉住测试（v0.5.0 元纪律）。
