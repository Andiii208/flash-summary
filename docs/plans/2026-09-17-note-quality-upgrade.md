# 笔记总结板块提升方案（Note Quality 2.0）

> 状态：**方案待审（v3）**。日期：2026-09-17。
> 触发：Andiii 要求系统排查笔记总结板块的提升空间——结构性、SVG 画图、与 GitHub 上成熟笔记 skills 的结合。
> **v3 定位修正（Andiii 裁定）**：**「我不喜欢教学，把总结做好就够了」**。本方案据此**整体收窄为「把总结做扎实」**——只做总结的忠实性、结构质量与呈现质量，**不做任何学习/教学功能**（v2 里的检索练习题型学、Cornell Cue 自测钩子、间隔重复、Anki 卡型扩张、个人思考输入区全部移除，见 §4）。同时修正 v2 的一处实质错误（图片采样，见 §0.4）。
> 证据基础：四路只读调研 + 本仓逐行核实 + GitHub skill 生态检索。所有结论带 `file:line`。

---

## 0. 结论先说

### 0.1 三个承重点

笔记模块**工程骨架已经很扎实**——单一 JSON 驱动五视图（`views.ts:13-15`）、三层证据对齐（`evidence.ts`）、纯函数布局（`mindmap-layout.ts`）、版本化留存、体检徽标、五条导出通道，这些都在而且干净。所以本方案**不改架构**，只补三个没支起来的承重点。

**① 素材层把时间信息扔了（最根本）**

`segments_json` 里存的是 `{at, text}`（`bilibili/subtitle.ts:65` 注释确认），但三处消费点全都经 `cleanTranscript` 只取 `text`：
- `summarize.ts:74` → `cleanTranscript(... as Array<{ text: string }>)`
- `polish.ts:56` → 同上
- `qa.ts:32-33` → 类型里写了 `at?: number`，但传给 `cleanTranscript` 后照样被忽略

`transcript-clean.ts:68-78` 只做 `cleaned.push(text)` 再 `join('\n')`，**时间被彻底丢弃**。但 prompt 要求模型：规则 1 所有 `at` 必须是**整数秒**（`summarize.ts:29`）；9.2 `refs.text` 是**转写原文的忠实摘引**（`summarize.ts:41`）。

模型唯一的公开时间线索是图片 caption，而其中**只有关键帧带时间**（`imageCaption` 对 `ppt:` 的 `at` 为 `null`，不发时间，`summarize.ts:91-95`）。

> **这是「evidence 引用遵循度弱」被反复记成观察项却始终不改善的真正原因——不是模型不听话，是模型没有信息。** 一条无从核验的引文，模型只能编。
>
> 证据强度说明：实测观察到的失败形态是**散文 ref**（如 `超参数调整演示幻灯片`，`schema.ts:168` 注释实录），不是照抄占位符。所以准确表述是：**缺时间是根因**，few-shot 缺陷（§0.2-A）是加重因素而非唯一成因。

**② 生成后没有质量闭环**

数组字段一律 `.default([])`（`schema.ts:105-119`），生成路径只解析不返修（`summarize.ts:153-157` 两次解析的是同一份文本）。结果：**一份 concepts / timeline / quiz 全空的「空壳笔记」是合法成功**。

体检还有真实漏洞（已核实）：`conceptFindings` 在 `concepts.length === 0` 时直接 `return []`（`health.ts:54`），`timelineFindings` 同理（`:72`），而「诚实空节」的 info 只覆盖 examCues / questionsAndGaps / quiz（`health.ts:83-89`）——**概念与时间线全空不产生任何 warn，warnCount=0 即判 good（`health.ts:112-113`）**。一份没有概念、没有时间线的笔记可以拿满分。

**③ 教学结构没有字段可放**

- `Concept` 只有 `term / definition / refs`（`schema.ts:35-39`）——**没有 example**
- `examCues` 是扁平 `string[]`（`schema.ts:111`），与 `knowledgeTree` 零关联
- `QuizItem` 无 refs（`schema.ts:57-63`）

所以「例子」只能塞进 `formulasAndSteps[].explanation` 的自由文本，「易错点」只能作为 methodology 里一个**建议的** `##` 小节（`summarize.ts:29` 规则 3）。**这直接削弱了总结本身**——一份不含具体例子的概念定义，读起来就是一句名词解释。

### 0.2 两处已验证的具体缺陷

**缺陷 A：prompt 的「唯一合法形态」few-shot 示范的是非法值**

`summarize.ts:46`（规则 9.7）写：

```
正确示例：{...,"evidence":[{"kind":"keyframe","ref":"kf:<证据ID>"}]}
```

而这一形态**过不了它自己的归一层**：`EVIDENCE_REF_PATTERN = /^(ppt:\d+|kf:[\w.-]+)$/`（`schema.ts:171`）——`<` `>` 不在 `[\w.-]` 字符类里，`kf:<证据ID>` 会被 `normalizeEvidence` 静默丢弃（`schema.ts:180`）。

它并不直接导致 0/8（实测失败形态是散文），但**在一个教协议的 few-shot 里没有一个合法取值**，等于没教。同一示例里时间线 `"at":750` 而 `refs` 写 `"at":10`，也在示范「ref 的时间与条目时间无关」——而正确语义恰恰相反（见批1）。

**缺陷 B：表格是「碰运气」能力**

- `looksLikeMarkdown`（`views.ts:132-134`）只检测 `#` / 列表 / 加粗，**不检测表格** → 一份只有表格（无标题无列表）的 overview 走纯 `<p>` 分支，把 `|` 原样印出来
- `md-lite.ts` **支持**表格（`:86-102`），`MdLite.tsx:63-89` 渲染为真 `<table class="md-table">` JSX
- `style.css:1048-1063` 有 `.md-table` 样式，而 **`print.css` 里 `table` 一词只出现在第 8 行的注释里**（已逐行核实）→ PDF 中表格完全无样式

### 0.3 本方案做什么、不做什么（v3 定位）

**做**（都服务于「把总结做好」）：
1. **忠实性**——让总结里的时间、引文、画面引用都经得起核验（批1）
2. **结构质量**——让概念有例子、考点有归属、关系有语义（批2 / 批5）
3. **呈现质量**——公式能看、表格不掉样式、导图不穿线（批4 / 批5）
4. **生成闭环**——不再放行空壳总结（批3）
5. **工艺沉淀**——把上面四件事写成可复用的契约（批6）

**不做**（v3 明确移除）：
- 检索练习题型学、自测钩子、Cornell Cue、间隔重复调度、掌握度追踪、错题本、Anki 卡型扩张、「个人思考」输入区——**任何学习/教学功能一律不做**。
- 已在 §4 逐条列明，并说明 v2 为什么会写进去（那是我理解错了定位）。

### 0.4 v3 修正 v2 的实质错误：图片采样不该「均匀化」

**v2 的错误**：我提出把图片选取从「PPT 全收 → 关键帧补 → `slice(0, 20)`」改成**沿时间轴均匀采样**。Andiii 指出东南大学平台本来就有现成 PPT、课程截图可用，质疑为何要全改成均匀采样。**核实后确认他是对的，我的方案是错的**：

- `orchestrator.ts:670` 的代码注释自己写着 **`// Platform PPT: primary visual source (best-effort; absence is not fatal).`**——**PPT 本来就是设计上的主视觉源**，均匀采样是在跟代码的设计意图对着干。
- 关键帧的来源流就叫 **`screen/PPT stream '1170195-5'`**（`streams.ts:4`）——**两条通道拍的是同一块屏幕**，它们不是二选一的关系，是同一信息的两种采集。
- 均匀采样会**主动丢掉 PPT 页**——恰恰是保真度最高、公式/图/表格最完整的那一份素材。

**v2 想解决的问题仍然真实**（扁平 `slice(0,20)` 会丢信息），但正确的解法是**融合而不是替换**，见 §1.6 与批1-4。

### 1.3 PPT × 关键帧：当前机制（融合方案的事实基础）

这是本方案最需要讲清的一节，因为 v2 就是在这里出错的。

**两条独立通道，拍同一块屏幕：**

| | PPT 通道 | 关键帧通道 |
|---|---|---|
| 来源 | 平台 API `/v1/course/ai/ppt?courseId=`（`school/client.ts:168`）→ `deps.school.listPpt`（`orchestrator.ts:678`） | `screen/PPT stream '1170195-5'`（`streams.ts:4`）按固定间隔抽帧 |
| 产物 | 整页幻灯片 PNG，`ppt/page-NNN.png`（`orchestrator.ts:685`） | JPEG 屏幕截图，文件名内嵌秒 `kf-0004-123s.jpg`（`orchestrator.ts:662`） |
| 去重 | 无 | phash 平均哈希 + 汉明距离 ≤5（`phash.ts:55`） |
| **时间** | **无**——`ref: ppt:N` 的 `at` 写死 `null`（`attachments.ts:29`） | **有**——`timestamp_seconds` 落库（`orchestrator.ts:659`） |
| 保真度 | 高（原始幻灯片，公式/图/表格完整） | 低（JPEG 截图，可能只拍到半页、被批注遮挡） |
| 设计定位 | **"primary visual source"**（`orchestrator.ts:670` 注释） | 兜底（`orchestrator.ts:690-692` catch 注释：PPT 失败时「keep keyframes as the visual evidence」） |

**四个关键事实：**

1. **PPT 是设计上的主源，但经验上常常为空。** PPT 的获取是 best-effort，失败静默吞掉（`orchestrator.ts:690-692`）。`docs/skills/note-craft/SKILL.md:40` 记录了当时的探针结论：「平台 PPT API 真实课程空返回，**实际素材 = 屏幕流关键帧**」。所以两条通道**都在，但可用性随课程而异**——融合方案必须两边都能降级。
2. **今天不是二选一，但也谈不上融合。** `summarize.ts:66-69` 只是把 PPT 排在前面、关键帧跟在后面，然后 `slice(0, MAX_SUMMARIZE_IMAGES)`（`=20`，`summarize.ts:16`）。两者之间**没有任何互相利用**。
3. **关键帧的抽取量远大于去重后**：SEU 课实测 45 分钟产出 **17 张关键帧**（`docs/acceptance/MVP.md:17`），说明 10s 抽帧（约 270 张候选）经 phash 去重后收敛到十几张。这个量级**通常低于 20 的预算上限**，所以扁平 `slice` 在 SEU 场景下常常并不真的丢东西——v2 我把它当成主要矛盾，是判断失准。
4. **反过来，PPT 页多的课程才是真问题**：一份 40 页的 PPT 加十几张关键帧就超预算了，而这时的取舍逻辑是「按类型排序后截断」，与信息价值无关。

## 2. 批次设计

六个批次，每批独立可交付、独立可验收。**全部服务于「把总结做好」。**

| 批次 | 一句话 | 主要触及 |
|---|---|---|
| 批1 | 素材层修复 + PPT/关键帧融合 | 忠实性（时间、引文、画面） |
| 批2 | 概念带例子 + 契约最小扩展 | 结构质量 |
| 批3 | 生成质量闭环（返修 + 体检补洞） | 不放行空壳总结 |
| 批4 | 公式 / 表格 / 代码呈现 | 呈现质量 |
| 批5 | 概念关系命题化 + 导图打磨 | 结构与呈现 |
| 批6 | 工艺沉淀（SKILL 2.0） | 防漂移 |

### 批1 素材层修复 + PPT × 关键帧融合

**目标**：让总结里的时间、引文、画面引用都经得起核验；让 PPT 与关键帧互相成就而不是各自为政。

1. **带时间喂入转写**：`cleanTranscript` 保留 `at`，产出 `[mm:ss] 文本`。三个消费点（summarize / polish / qa）统一受益。
   - 兼容性：`RawSegment` 的 `at` 保持可选，缺 `at` 的段退化为纯文本行——**不报错、不阻塞**。
   - **B站细粒度字幕必须分组**（工程约束，非优化项）：B站字幕逐句 cue 约 **2-3.5 秒/条**（测试夹具实录 `tests/bilibili-client.test.ts:154`：`0.2→3`、`3→6.4`；`:159-160`：`0.5→2.4`、`2.4→4`），45 分钟可达上千条，逐条加 `[mm:ss]` 每课多约一万字符。按 **30s 时间窗或语义空行分组**后再加时间戳（约 90 条/课）。SEU 源本来就是 120s 分片（`openai-client.ts:41`「≤120s audio」），不需要这条。
2. **生成后核验 ref**（新增纯函数 `src/shared/notes/ref-verify.ts`）。两条可机械判定的不变量：
   - **timeline 条目的 `refs[].at` 应落在该条目 `at` 的邻域内**（邻域宽度按源分档：SEU 120s、B站 60s）——修复 9.7 few-shot 示范的错误语义
   - **`refs[].text` 应能在原始转写里模糊匹配到**（复用 `bigramDice`，阈值放宽到 ≤0.7 以免误杀合法摘引；概念的 refs 只要落在真实 segment 范围内即可）
   - 不可核验的 ref **降级而非报错**：`text` 不匹配则清空 `text` 保留 `at`；`at` 越界则丢弃该 ref
3. **修正 9.7 few-shot**（缺陷 A）：`kf:<证据ID>` 换成合法占位（如 `kf:k7`），示例内 `refs[].at` 落在时间线 `at` 邻域。
4. **PPT × 关键帧融合**（本节核心，替代 v2 的错误方案）：
   - **(a) 交叉去重——只丢冗余不丢信息**：用同一套 phash（`phash.ts` 已有 `averageHash` / `hammingDistance`）把关键帧与 PPT 页做视觉匹配。关键帧若与某 PPT 页近乎相同 → **保留 PPT 页**（更清晰），该关键帧不必再发；**与任何 PPT 页都不匹配的关键帧必须全部保留**——那正是 PPT 之外的信息（板书、现场演示、软件操作、讲者手写标注）。
   - **(b) 用关键帧给 PPT 反推时间——融合的核心收益**：匹配上的关键帧都带时间戳（`orchestrator.ts:659`），PPT 页有顺序（`page_index`）。把「关键帧 i ↔ PPT 页 j」按时间排序，即可给 PPT 页分配**单调递增的时间轴**（PPT 页 j 的时间 ≈ 它首次出现的匹配关键帧的时间）。
     → **`ppt:N` 从「无时间锚」变成「有时间锚」**，模型可以在 timeline 里引用**高保真幻灯片 + 真实时间**，而不是二选一。这直接补上承重点①的「让时间可用」。
     → 注意 `attachments.ts:29` 现在写死 `at: null`，需要改为可携带推断时间；**推断时间必须与精确时间在数据上可区分**（例如加 `atInferred: true`），否则 UI 会把推断值当实测值展示。
   - **(c) 预算法——绝不砍 PPT**：现在是「按类型排序 → `slice(0,20)`」（`summarize.ts:66-69`），与信息价值无关。改成：PPT 页全发（它们是幻灯片正文）→ 关键帧按「与 PPT 不匹配优先」+「时间轴覆盖率」排序 → 超预算时**先砍与 PPT 冗余的关键帧，再砍覆盖率低的关键帧，绝不砍 PPT 页**。
   - **(d) 两边都能降级**：PPT 常常为空（§1.3-事实 1），此时行为**与今天完全一致**（全部关键帧）；关键帧为空时（B站风控拒绝，SKILL §8 已记为合法态）只发 PPT。
5. **两个指标，两个口径**（v2 修正，仍然成立）：
   - **`resolveEvidenceRefs`（合法性）**用**全量**证据集。现在生成侧只用「实际发送的 ≤20 张图」当 validRefs（`summarize.ts:215-216`），导致**真实存在但未发送的证据被当编造删除**；polish 却用全量（`polish.ts:64-71`）——两通道能力不对等。
   - **`evidenceHitRate`（遵循度）**用**发送集**当分母。否则一份 40 页 PPT 只发 20 张时，上限恒为 0.5，徽标永远报警、指标不可行动。现在它只算 timeline 的视觉 ref（`evidence.ts:176-186`），顶层 `evidence` 不计——一并修。
   - 新增 **`transcriptRefHitRate`**（转写锚可核验率），三者并列暴露。

**不做什么**：不改视图，不改 prompt 的质量下限，不改 UI 文案承诺。旧笔记无需重跑。

**验收**：真实库副本重新生成 3 课（SEU ASR ×2 + B站 ×1），对比 `refs` 可核验率、`at` 越界数、邻域违例数；**融合专项**：构造「PPT 有 / PPT 空 / 关键帧空」三种素材组合，断言每条通路的取图集与预期一致；**并把 PPT 页的时间推断结果与实际关键帧时间对照抽样人工过目**（防止单调映射跑偏）；纯函数单测覆盖六场景；四门禁全绿。

### 批2 概念带例子：契约最小扩展

**目标**：让总结里的概念是「有具体例子的概念」，而不是一句名词解释。**只加一个字段。**

**契约扩展**（可选带默认值，**旧笔记零迁移**——与 M2.1 `terms` / M3.1 `conceptLinks` 同一手法）：

```
Concept += example?: string   // 本讲出现的具体例子 / 应用场景（含数字与参数）
```

- **v3 收敛**：v2 还打算加 `misconception` 与 `TreeNode.cues`。前者主要服务于「错误侦测题」、后者服务于「自测钩子」——**都随教学定位一起移除**（`TreeNode.cues` 降级为 D6 观察项）。
- `QuizItem` **不加任何字段**：`QuizItem.term` 已存在（`schema.ts:62`），quiz 维持现状，本方案不动它。

**prompt 条款**（进 `NOTE_QUALITY_PROMPT`，配 `tests/note-prompt-quality.test.ts` 钉住断言）：
- 9.9：`example` 必须是本讲出现的**具体**例子（含数字/参数/操作），禁止「例如在实际应用中」式空话；讲者没给例子就省略该字段（**宁空勿编**，与 9.4 / 9.5 同纪律）

**同步清单**（note-craft SKILL §0 的契约纪律）：zod schema + 归一层、两个投影（`projectNote` / `projectNoteBlocks`）、`markdown.ts`、`PrintHandout.tsx`、`obsidian.ts`、`anki.ts`、测试。其中 obsidian/anki 是 v2 补的——**Anki 卡背面是否带 example** 见 D7。

**视图落点**（不动五视图结构，只在既有块内加内容）：
- 概念卡：`example` 作为定义下方的次级行（**必须走 `InlineText`**——AGENTS 硬规定，2026-09-12 刚因违反它出过 `**` 字面事故）
- 体检：`example` 缺失**不报 warn**（宁空勿编），存在率作为 info 暴露

**文档同步**（AGENTS 一致性纪律）：spec §5 的 schema 清单**已落后于实现**（`quiz` / `conceptLinks` / `terms` / timeline `evidence` 都不在清单里），§11 第 9 条仍写「four views」（`spec:192`）与 §5 修订的五个视图冲突。一并更新。

**验收**：契约扩展归一层单测（合法 / 非法 / 缺失）；旧笔记（无新字段）加载快照零变化；投影 / 渲染 / obsidian / anki 测试；PDF 产物人工过目一次。

### 批3 生成质量闭环：从「事后体检」到「生成时返修」

**目标**：不再放行空壳总结。范式来源：ultramath 的「阶段门禁未过不得进入下一阶段」与 gzhflow 的「每阶段带质量门」（**这两份是本机辅助 skill，只借范式不引文本**）。

1. **`noteHealth` 接入生成路径**：`generateNote` 解析成功后立即跑体检，`warnCount > 0` 时带 findings 做**一次** bounded 返修（findings 作为 user 消息追加，要求只修不重写）。
   - **返修不发图**（v2 修正，仍成立）：只带 findings + 原输出 + 带时间转写。返修若重发图片，多模态费用接近翻倍；而 findings 基本都是「写短了/复读了标题/没有具体数字」，靠转写文本就能修。
   - 返修后仍不达标就**照常出笔记**（退化为现状）+ 体检徽标提示。
2. **补体检的洞**（§0.1-②）：
   - `conceptFindings` / `timelineFindings` 在数组为空时直接 `return []`（`health.ts:54,72`）→ **一份概念与时间线全空的笔记能评 good**。改为对「必填分节缺失」报 warn。
   - 补上 prompt 有要求但体检不测的项：时间线条目数、`detail ≥60` 逐条（现为 bigram 启发式）、`knowledgeTree` 分支数/层数/标题 ≤20 字。
   - 区分「模型没写」与「被归一层丢弃」。
3. **归一化诊断可见**：`parseNote` 增加返回丢弃计数（quiz / evidence / terms / links 各丢几条、原因）。落库并进体检 findings，让「模型编了 8 条 ref 全被拦下」变成看得见的事实，而不是「内容有点少」。注意这会改 `parseNote` 的返回形状，调用点与测试需同步。
4. **笔记行记录 `promptVersion` / `schemaVersion`**（新增 migration **011**，现有 migrations 到 `010_obsidian_exports`）：解决升级判定的漏洞——`NoteUpgradeDialog` 只认 `warnCount > 0`（`NoteUpgradeDialog.tsx:12-14`），旧 prompt 生成但侥幸 warn=0 的笔记永远不会被建议升级。
5. **polish 对齐**：`POLISH_SYSTEM_PROMPT` 要求「转写同音错词结合画面纠正」（`polish.ts:33`），但 `polish.ts` 是纯文本调用、不发图（`:103` 起的 `chatJson` 无 `image_url` part）——**设计与实现的直接漂移**。二选一：补发少量关键帧，或删掉该条款。建议**补发**（同音错词纠正是已实证的高价值能力）。同时 `MAX_TRANSCRIPT_CHARS = 24_000`（`polish.ts:20`）让长课后半段无素材，改为按课时长度自适应。

**关键纪律：自动返修，不阻断用户。** 返修上限 1 次；不达标照常出笔记。理由是 Andiii 的既定品味是反门控——生成失败弹窗比一份及格的总结更糟。**门禁只用于内部提质，绝不用于拦截交付。**

**验收**：返修路径单测（构造 warn>0 的假输出，断言触发一次且不再触发第二次）；体检补齐项逐条单测；**空 concepts 不再评 good 的回归测试**；migration 011 幂等测试；真实库重生成对比（返修前后 warnCount）。

### 批4 呈现质量：让已有内容正确显示

全是渲染层，**不动数据契约、不动 prompt**。但要过打包关。

1. **数学公式渲染（KaTeX）**——价值最高的单项。`kind:'formula'` 字段已在，只差渲染器。
   - **守住 md-lite 铁律的写法**：SKILL §3 的铁律是「解析器只产 token 数组，绝不产 HTML 字符串」。所以 **parser 只产出 `{t:'math', tex}` token**，渲染层**用 `katex.render(tex, el)` 渲染进一个 ref 容器元素**——不经过 `renderToString` + innerHTML，铁律完整守住。
   - **打包关（本批最大的隐藏成本）**：`electron.vite.config.ts:15-22` 的 `drop-legacy-woff` 插件专门剥 @fontsource 的 legacy woff，**刚在 2026-09-14 省掉 500 个 woff / 约 17MB**。它的门是 `id.includes('@fontsource')`，**KaTeX 的 CSS 不会被处理**；且正则只剥 `.woff`、不剥 `.ttf`。KaTeX 自带约 60 个字体（woff2 + woff + ttf）。不做处置就引 KaTeX，等于把刚省下的体积部分还回去。
     - 处置：把插件判断从「按包名」改为「按是否 @font-face 字体 url」，并同时剥 `.woff` 与 `.ttf`。**打包后必须复核 `out/renderer/assets` 的字体文件数与包体积**，写进门禁。
     - 另一条路见 D1：KaTeX 的 **MathML-only 输出**（`output: 'mathml'`）在 Chromium 上原生渲染，**零字体**，代价是排版保真度略低。
   - 行内 `$...$` 与块级 `$$...$$` 两种；`PrintHandout` 同源复用（PDF 讲义的公式才是主交付物）。
   - 新运行时依赖 → 按 AGENTS 同步 `THIRD-PARTY-NOTICES.md` + `LICENSES/`（KaTeX 为 MIT）。
2. **表格修复（缺陷 B）**：`looksLikeMarkdown` 加表格检测（一行 + 下一行是 `|---|` 分隔）；`print.css` 补 `.md-table` 规则（参照 `style.css:1048-1063` 的令牌，但按 SKILL §6 强制纸白）。
3. **代码高亮**：`NoteBlocks.tsx:299-302` 的 `<pre><code>` 接轻量高亮。若不想引依赖，退一步做「等宽 + 行号 + 纸白底」也能拿到八成收益。**本批最后做，预算不够就整体后移**（见 D8）。

**注**：本批新增的是「显示能力」而非「新承诺」，不触发 spec §9 声明层流程；但若要在 README 宣称「支持公式渲染」，需按 AGENTS 声明层纪律确认措辞与事实一致。

**验收**：`tests/md-lite.test.ts` 扩语法用例；`tests/note-viewer.test.tsx` / `tests/print-handout.test.tsx` 渲染断言；真实数据跑 `node scripts/ui-shots.mjs` + DOM 计数探针（SKILL §7）；PDF 导出跑完整按钮流 e2e，检查公式为矢量文本而非图片；**打包复核字体数与 Setup 体积不反弹**。

### 批5 概念关系命题化 + 导图打磨

**目标**：`conceptLinks` 被限在 ≤5 条、只画虚线、标签是噪声、还会穿节点。

0. **先修语义，再修画面**（§1.5.4-②）：PROGRESS 记录过「conceptLinks 3 条解析 100% 但 **label 偏噪声**」。吸收 D（概念图的价值在**命题结构**与**命题审计**）后可看出这是**必然而非偶然**：一条链接只有 `{from, to, label}`（`schema.ts:74-78`），画出来是一条带 2-4 字标签的虚线——**既构不成可判定真假的命题，也没有任何质量指标**。
   - 处置：`label` 从「关系词白名单」升级为**有原则的关系分类**——吸收 E 的四分类 **汇聚 / 扩展 / 张力 / 矛盾**，并明确「表观矛盾不要人为消解」。
   - 新增**命题审计**口径进体检：每条链接能否读成「A ——关系—— B」的可判定命题（现有 12 字长度守卫只能挡超长，挡不住「参数、提升、方法」这类名词填充）。
   - **这一项优先级最高**：先让数据有意义，再让它好看。
1. **导图关联线避让**：`linkPath`（`mindmap-layout.ts:251-264`）在两节点横向重叠时返回 `M x1 y1 L x2 y2` 中心直线，**必然穿过节点**（已核实源码）。改为按层间走廊路由（正交折线）。
2. **「关系模式」作为导图视图内的第二种呈现**（**不新增第六视图**）：现有导图是层级树，加一个切换——把 `conceptLinks` 作为主结构画成概念关系图，全部链接可见（不再只画 ≤5 条）。布局沿用既有纯函数风格（确定性、可测），不引 d3。
   - **为什么放进现有视图**：spec §5 修订批注①把五视图钉住了（「四扩为五」是 2026-09-04 用户批准的）。新增第六视图**不是禁止**，但需要先做一次 spec 修订（有先例）。按 AGENTS「两种方案犹豫时选更简单的」，推荐前者。见 D2。
   - 同时把 `conceptLinks` 的 ≤5 条上限适度放宽（prompt 侧，`summarize.ts:29` 规则 8）。
3. **导图 PNG 导出**：SVG 管线已铺好（`ipc.ts:1272-1306`），加 bitmap 输出。零新依赖可行（SVG 只含 text/rect/path，无外部引用，renderer 侧 canvas 光栅化不污染画布）。
4. **性能门禁**：边收集 O(n²)（`mindmap-layout.ts:223-226`）改为 Map 索引；补「千节点布局耗时」基准测试（阈值放宽，只防明显退化）。

**验收**：`tests/mindmap-layout.test.ts` 补避让与关系模式的确定性用例；命题审计的单测（噪声 label 必须被判不通过）；性能基准进测试套件；真实库课程级导图截图过目。

### 批6 工艺沉淀：note-craft SKILL 2.0

**目标**：把前五批固化成仓库自己的工艺契约，并登记外部方法来源。

1. **SKILL 升级为「五阶段 + 每阶段门禁」**（范式来源：ultramath 的阶段门禁、gzhflow 的每阶段质量门）：
   ```
   素材（转写+图 → 带时间的清洗文本 + PPT×关键帧融合）
     → 生成（prompt 形状规约 + 内容规约）
     → 核验（ref 可核验性 + noteHealth）
     → 返修（bounded 一次，不发图）
     → 投影（五视图 / 导出 / 关系图）
   ```
   每个阶段写清「输入契约 / 输出契约 / 门禁」。
2. **新增一节给 PPT × 关键帧融合**（§1.3 的机制事实 + 三条融合规则），因为现在 SKILL §1 只写了「三层证据对齐」，没写两条视觉通道的关系。
3. **修订 §9「方法论参照」**：
   - 「社区没有可直接照搬的「LLM 笔记生成工艺」skill」**已过时** → 改写并登记本次调研的保留候选（C/D/E/G/I）。
   - **明确记一笔「教学向 skill 已评估不采纳」**：把 `active-recall-practice` / `flashcard-generation` / `spaced-repetition` 等列进去并写明理由（产品定位是生成总结，不做学习功能）——**防止下一个会话又提一遍**。
4. **新增「外部方法论吸收登记」小节**：候选清单、许可结论、边界。**这是防止许可事故与定位漂移的制度化落点。**
5. **「去 AI 味」总结版条款**（总结的 AI 味与文章同源：太均匀、太正确、太完整）：
   - **去路标**：禁「值得注意的是」「综上所述」「本节主要介绍」式模型路标（这类词在 ASR 转写里根本不存在，出现即模型加的）
   - **具体 > 抽象**：概念定义必须落到本讲的具体数字/参数/演示结果（强化既有 9.1 / 9.2）
   - **不均匀化**：不要求每条概念等长、每条时间线含相同要素——避免「每条都齐整」的模板感
   - **诚实说明测试边界**：`tests/note-prompt-quality.test.ts` 只能钉住**条款存在性**，不能钉住**模型行为**。模型是否遵守只能靠真实库 e2e 抽检。方案不拿测试绿当质量证明（SKILL §7 已要求真实数据验证）。
6. **与 agent-capability 方案的会师点**（回应 `docs/plans/2026-09-17-agent-capability-exposure.md`）：那份方案的 `note_get` / `document_export` 返回的 markdown 必须过**同一套工艺保证**（同一份 `shared/notes/*` 投影）。批6 在 SKILL 里写死这条。

**验收**：SKILL.md 版本号 1.1.0 → 2.0.0；新增 prompt 条款的钉住测试；前五批实现与 SKILL 逐条对照无漂移。

## 4. 明确不做

### 4.1 学习 / 教学功能（v3 新增，Andiii 2026-09-17 裁定）

**产品定位是「把总结做好」，不做学习功能。** 以下均不做，且已从 v2 移除：

- 检索练习题型学（题型配比 / 禁是非题 / 诊断性答案 / 会话内排序）——v2 批2 的 9.12，已删
- 自测钩子 / Cornell Cue 自测化 / `TreeNode.cues`——降级为 D6 观察项
- `Concept.misconception`——已删（其价值主要来自「错误侦测题素材」）
- 间隔重复调度器（FSRS/SRS）、掌握度追踪、错题本、今日队列、学习进度可视化
- Anki 卡型扩张（Cloze 挖空 / 图像遮挡卡）
- 「个人思考」等用户自写输入区
- quiz 的任何升级——**quiz 维持现状（5-8 题 Q/A），本方案不动它**

> 已评估并明确不采纳的外部 skill 记录在 §1.5.1 末，并在批6 写入 SKILL，防止下一个会话重提。

### 4.2 其他既定边界

- **不删顶层 `transcriptRefs`**——它全链路无消费（死字段），但 **spec §5 明文要求 note schema 包含「Timestamped transcript references」**（`spec:86`）。保留该字段，允许在批6 的工艺文档里标注其语义待接入。
- **不做时间戳跳转视频**——硬约束：本地视频已删、平台播放页无时间参数（SKILL §8）。
- **不做笔记在线编辑器**——既定边界。
- **不做跨课时概念链接 / 课程级概念图谱**——既定产品边界；spec §12 明文 deferred。**批5 的关系图严格限定在单课时内的 `conceptLinks`**。
- **不换导图库**（不引 markmap/d3）、不做力导向/鱼骨/矩阵/流程图模板。
- **不生成多份独立总结**——spec §5 硬约束（`spec:74`），五视图必须同源同一份 JSON。
- **不改 `md-lite` 铁律**——parser 只产 token 数组；KaTeX 只在渲染层调 `render()` 进容器元素。
- **不在本方案处理笔记库可达性**：`notes:list` 有 `LIMIT 200`（`ipc.ts:1098`），旧笔记不可达、且笔记库无搜索。这是**真实缺口**，但属于「笔记库」而非「笔记总结」，且 2026-09-13 刚动过笔记库观感。列为已知缺口，建议下一轮单独处理。
- **不做云端 / 多用户**——MVP 边界。
- **不动 UI 视觉令牌体系**，不新增弹窗形态，不新增 busy 形态（AGENTS UI 约定）。

## 5. 风险与纪律

| 风险 | 处置 |
|---|---|
| **PPT 时间反推出错**（D5-A） | 推断时间必须与实测时间在数据上可区分（如 `atInferred: true`）；单调映射必须做**单调性断言**；抽样人工对照真实关键帧时间 |
| 契约扩展破坏旧笔记 | 新字段可选带默认值；旧笔记加载快照测试钉住；参照 M2.1 `terms` / M3.1 `conceptLinks` 的既有手法 |
| **引 KaTeX 导致包体积反弹** | 扩展 `drop-legacy-woff` 匹配范围 + 剥 `.ttf`；打包后复核字体数与 Setup 体积，写进门禁 |
| KaTeX 与 md-lite 铁律冲突 | 用 `katex.render(tex, el)` 渲染进 ref 容器，**不经过 HTML 字符串**；写进 SKILL §3 |
| 新依赖合规 | KaTeX → `THIRD-PARTY-NOTICES.md` + `LICENSES/`（AGENTS 硬规定） |
| **返修成本翻倍** | 返修不发图，只带 findings + 原输出 + 带时间转写；耗时与 token 增量记入任务阶段日志 |
| 核验函数误杀合法摘引 | 阈值放宽（`bigramDice` ≤0.7）；不匹配时降级保留 `at` 而非整条丢弃 |
| **指标口径失真** | 合法性与遵循度**两个口径分开**，不合并；UI 徽标要写清是哪个口径 |
| B站字幕粒度导致 token 膨胀 | 按 30s 窗/语义分组后再加时间戳；接受 SEU(120s) 与 B站(秒级) 的精度不对称并在 UI 说明 |
| **定位漂移回教学** | §4.1 列明不做项；批6 把「已评估不采纳的教学向 skill」写进 SKILL 备查 |
| 真实数据未验证就宣称提升 | 每批必须跑真实库副本 e2e（SKILL §7 硬要求），不拿测试绿当质量证明 |
| 文档与实现再次漂移 | 批2 同步 spec §5 清单与 §11 第 9 条；批6 固化 SKILL 2.0；每批结束跑一致性检查（AGENTS） |
| 测试数只增不减 | 每批新增测试，不许 skip / 删断言 / mock 关键路径（AGENTS 红线） |

## 6. 优先级建议

建议落地顺序：**批1 → 批4 → 批2 → 批3 → 批5 → 批6**。

- **批1 最优先**：它是其余一切的前提（没有可核验的引文与时间，批3 的核验建在沙上），而且 **PPT × 关键帧融合**是这次最实在的一块改善——它让总结里的画面引用从「有什么发什么」变成「高保真幻灯片 + 真实时间」。
- **批4 提到批2/批3 之前**：公式 + 表格是用户能**立刻看见**的改善（SEU 理工课的总结里公式原样印 `\frac` 是硬伤），成本低、无契约风险。但 D1 的打包决策要提前做，否则会被体积门禁挡回。
- **批5、批6 可延后**：结构与沉淀，不影响「总结是否好用」这个核心判断。

**最小可用组合**：只做批1 + 批4，拿到约六成可感收益（引文真实 + 公式能看 + PPT 用对）。

## 7. 本方案不依赖的假设

- 不假设模型能力有变化——批1 的改善来自「给模型它本来就该有的信息」，不是换模型。
- 不假设平台 PPT API 一定可用——融合方案两边都能降级（§1.3-事实 1），PPT 为空时行为与今天一致。
- 不假设引入了新的 ASR 能力——`docs/health/2026-09-04-asr-timestamp-probe.md` 已实证平台不支持 segment 级时间戳（维持 120s 分片）。本方案接受该粒度，用批1 的核验机制诚实降级，并用 B站源（秒级）作对照。
- 不假设用户会重跑全部历史笔记——所有新能力对旧笔记零迁移。
- **不假设产品要变成学习工具**——§4.1。
