## 〇、设计原则基线（外部规范对照结论）

本次审查用两条外部规范做标尺，所有问题的定性都挂靠其中：

- **NN/g 一致性启发式**：界面内部各视图必须保持一致（internal consistency），不一致会增加认知负荷；用户预期由他们最常用的其他产品塑造（Jakob 定律）。→ 主诉 3「排版混乱」的直接依据：一个应用里混用 5 种对齐/宽度基准。
- **WinUI NavigationView 指南**（Windows 应用官方导航规范）：①左上角是返回按钮的家；②每个导航类别应有**页头（Header）**显示当前位置——「其目的是承载所选导航类别的页面标题」；③导航体验必须**在整个应用中一致**；④设置入口约定俗成放在导航**底部**。
- **NN/g 状态可见/you-are-here**：用户在任何时刻都应知道「我在哪、当前操作对象是什么」。→ 主诉 1/2 的定性：左上角品牌区死了、追问页失去操作对象身份，都是「you-are-here」缺失。

## 一、问题取证清单（5 主诉 + 12 审查发现）

### 主诉区（Andiii 原话 → 根因）

#### M1 左上角点不回首页（「没有点击左上角回到最开始页面的功能」）

**根因**：`TopBar.tsx:29-34` 的 `.brand`（Colonnade 图标 + h1「SEU Summary」）是纯静态展示，无 onClick、无 title、无 role——既不是按钮也没有任何可点击暗示。而「点左上角回首页」是 Web（站点 logo → 首页）与桌面应用（左上角 = 返回/Home）双料惯例。
**叠加事实**：「最开始页面」本身没有归宿——应用没有「欢迎页/首页」概念，启动即四页签。用户想「回到一开始」时唯一能做的是逐个收起侧栏、取消选中课时，无处可去。

#### M2 追问页不知道在问哪节课（「没有提示你是对哪节课进行的追问」+「整体使用逻辑不清晰」）

**根因**：`QaPanel.tsx:41` 标题固定为「本课时追问」，面板内**零课时身份信息**：
- 已选课时：只有 `hasLesson` 布尔（QaPanel.tsx:15），课时身份要靠左侧课程树的选中行反推；placeholder「针对当前课时提问…」（QaPanel.tsx:88）同样不指名。
- 问答气泡（qa-pair）无任何时间与课时信息；`qa:history` 返回 `created_at`（ipc.ts:952-958）但渲染层丢弃（app.tsx:691 只取 question/answer）。
- 唯一显示「课程 · 课时」的地方是未选课时的「最近追问」列表（QaPanel.tsx:48）——恰好在最不需要它的空态里。

#### M3 排版混乱：有的靠左有的居中（「之前整体很协调，新版就没统一靠左了」）

**根因**：上一轮整改（field-ux-fixes 批A「阅读列居中」）只改了一半。现状 5 种基准并存（实测截图核对）：

| 页面/区域 | 宽度基准 | 对齐 | 证据 |
|---|---|---|---|
| 任务页标题+列表 | 无限制（全宽） | 靠左 | style.css 无 .task-panel 规则 |
| 追问对话流/输入行 | 780px 居中 | **居中** | style.css:879/903（margin-inline:auto） |
| 笔记正文阅读列 | 660px 居中 | **居中**（卷头还水平居中） | style.css:1164-1190 |
| 导图视图 | 破格全宽 | 全宽 | style.css:1172 |
| 设置页 | 760px 居中 | **居中** | style.css:917 |
| 各页 h2 大标题 | 全宽 | 靠左 | style.css:306 |

同一屏内：页签行靠左 → 工具栏全宽 → 正文居中 → 大标题又靠左。**Andiii 的裁决偏好已明确：统一靠左**（右侧空白是可接受的「字典区」留白，比强行居中的错位感协调）。

#### M4 思维导图折叠效果不好看（「点击前一个节点收起后面分支的时候显示效果不太好看」）

**根因**（代码 + 截图取证，MindMap.tsx / mindmap-layout.ts）：
1. **整树瞬间重排、无任何过渡**：`toggle` 改 collapsed 集 → `computeMindMapLayout` 全量重算 → 所有节点/连线坐标瞬间跳到新位置。视觉上「整棵树抽搐了一下」，而不是「这根枝条收起来了」。
2. **折叠态视觉弱**：折叠后只在节点**尾部**叠一个 8px 小圆徽标（MindMap.tsx:70-75）+ 文字后拼「…」（MindMap.tsx:68）。指示器不在视觉动线上（右侧是分支方向），且没有任何「可点击折叠」的 hover 之外的暗示；截图审查确认：**完全展开的树上找不到任何折叠指示**。
3. **层级无视觉区分**：根节点深绿底、其余全部同款浅灰盒（style.css:1146-1152），子层与孙层无差别；连线全同色 1.6px（mindmap-edge），视觉上分支混作一团。
4. **触发命中区小**：可折叠判定在 `<g>` 上，有效点击区=盒子本身；没有整行命中、没有折叠专属热区（chevron 区）。

#### M5 还存在其他反常识/反习惯设计（审查发现 12 项，编号 D1-D12）

### 审查发现（每条附代码证据）

#### D1 选中课时后任务页只显示裸 ID 回退
TaskPanel.tsx:96 显示「已选课时：{lessonLabel ?? currentLesson}」——lessonLabel 为 null 时直接显示 `1690625-L0` 这类原始 ID。侧栏有完整课程树数据却不用。（M2 同源：身份显示系统性缺失）

#### D2 笔记页视图切换会重置，且与「上一节/下一节」导航打架
NoteViewer 内部 useState view（NoteViewer.tsx:71），切换课时（onNavigateLesson）后**视图保留**——从「思维导图」切到无笔记课时再切回来，预期延续但新用户会困惑；反向问题：五视图不持久化，离开笔记页再回来总回到「详细笔记」。（低优先级交互不一致）

#### D3 追问提交后输入框清空、无提问回显前的乐观占位
QaPanel.tsx:36-38：submit 先 setDraft('') 再 onAsk；busy 时只有「思考中…」孤行（QaPanel.tsx:81），用户的问题不显示，直到 answer 返回。慢网络下用户不知道自己问了什么、是否提交成功。（NN/g：系统状态可见性）

#### D4 追问页无笔记课时也允许提问
qa:ask（ipc.ts:935-953）在 note==null 时照常组装上下文提问（assembleContext 拿不到笔记就给空上下文）。用户对未生成笔记的课时提问会得到与笔记无关的泛泛回答，且无任何「此课时尚无笔记，回答不基于笔记」提示——**静默的语义偷换**。

#### D5 设置页「笔记导出/日志」两个打开按钮挤在同一行
SettingsPanel.tsx:112-121：一行塞两组「标签+按钮」，标签宽度 64px（settings-label），视觉上是四个按钮排队，无分组边界。截图审查同样指出按钮尺寸/分组不统一。

#### D6 会话过期在 TopBar 只显示「已过期」徽标，但登录按钮不换文案强化
TopBar.tsx:52：expired 时按钮仍显示「重新登录」——这条尚可；但徽标「已过期」无 title 解释、不可点击，发现问题全靠用户自己 hover。（小项）

#### D7 任务页「已选课时」行与「创建并运行」按钮之间无视觉分组
TaskPanel.tsx:96-108：选中信息（msg）、主按钮、取消按钮、重跑提示、进度卡、历史列表**全部纵向堆叠无分隔**，无卡片容器。与设置页的 settings-block 卡片语言不一致。（M3 同源）

#### D8 空态两级待遇不统一（历史遗留清单第③条，仍在）
EmptyState 卡片 vs `.msg` 灰字两种空态样式并存（TaskPanel.tsx:82 用 EmptyState，QaPanel.tsx:43 用 msg）。同一应用同类场景两种视觉语言。

#### D9 主页签无键盘 Ctrl+数字 快捷键、无全局快捷键
四门禁内 grep 全 main 无 globalShortcut/Menu 注册。桌面应用惯例（浏览器 Ctrl+1-9、VS Code Ctrl+1...）完全缺失；页签虽有 roving focus 但鼠标用户与键盘用户都无快速通道。

#### D10 收藏星标无「已收藏」状态的视觉正反馈（title 有但样式弱）
CourseTree 星标 hover 才亮；收藏后无 toast、星标填充态对比不足，「我的收藏」组不自动展开提示。截图上星标与课时徽标视觉竞争。

#### D11 markdown 导出/复制不提示导出后文件在哪
导出 toast 只说成功；exports 目录用户不知道（设置页有「打开导出目录」但藏在设置里）。导出成功 toast 应带「打开目录」动作。（NN/g：闭环反馈）

#### D12 浅色主题下 --text-muted 灰字对比度在部分小字号上贴 AA 下限
--text-muted #667085 在 11px/12px 小字（hint 类）上 4.5:1 临界。deepseek-eyes 审查两度提到「部分文字对比度不足」。（微项，批量调一档）

## 二、整改方案（六批，按依赖与收益排序）

> 总设计裁决（需 Andiii 拍板，见决策点 1）：**全应用统一「左对齐 + 单一内容列」系统**——内容列统一 `max-width: 860px`、一律靠左（不居中）、页签/工具栏/正文共享同一左缘；导图视图唯一破格全宽。这同时回应 M3 主诉与「右侧留白协调感」偏好。

### 批 A：导航骨架——左上角回首页 + 全局页头（M1 + M5-D7 部分）

**A1 品牌区可点击 = 回到起始页**（TopBar.tsx）
- `.brand` 改为 `<button>`（type=button），点击行为 = 「回到开始」：清空当前课时选中（currentLesson=''）、切到任务页、侧栏滚动回顶。cursor:pointer + hover 微抬升 + title「回到起始页」。
- 等价语义：桌面应用左上角 = 回到起点；Web logo = 首页。两个惯例同一落点。

**A2 增设「起始页」语义（不新增页面，零新路由）**
- 定义起始态 = 无选中课时 + 任务页。品牌点击、以及设置页 C8 登录后的「去选课」之外，增加 TopBar 品牌旁一个轻量面包屑：`SEU Summary / 课程名 / 课时名`（选中课时才出现，可点击逐级返回——点课程清课时）。
- 面包屑即 WinUI「Header 页头」职责：任何时刻回答「我在哪、操作对象是谁」。

**A3 各页统一页头行**（取代现在裸 h2）
- 每页顶部（tabs 下方）：`页标题（h2） + 右侧上下文胶囊`。上下文胶囊全应用唯一组件 `LessonChip`：`课程名 · 课时名`，点击展开课时快速切换面板（复用现有 selectLesson），含 title 全名。
- 任务页用它替掉「已选课时：裸ID」（D1 根治）；追问页见批 C；笔记页卷头已有、不再重复。

验收：任意界面点击左上角回到起始态；任何页都能看到当前课时身份；TaskPanel 无裸 ID 路径（lessonLabel 永远有值或显示「未选择」）。组件测试：面包屑渲染/点击行为、LessonChip 渲染与空态。

### 批 B：布局统一——单一内容列系统（M3 主裁决）

**B1 内容列令牌化**：新增 CSS 变量 `--content-max: 860px`（约 44-48 CJK 字/行的舒适阅读上限；比 780 宽给任务列表留行内按钮空间）。
**B2 统一靠左**：`.qa-log/.qa-input-row/.settings-panel/.provider-form/.note-library/.qa-recent` 移除 `margin-inline:auto`，全部改 `max-width: var(--content-max)` 靠左。
**B3 笔记阅读列微调**：`.note-body` 从 660px 居中 → 680px 靠左（阅读列比工具列窄是刻意的排版层级——「正文在纸面上，工具贴左缘」；卷头 masthead 跟随阅读列左对齐，不再水平居中——「试卷头」意象本身是横排卷头，居中与靠左都成立，靠左与全局一致）。
**B4 页签行与工具栏对齐左缘**：tabs 行、note-toolbar 左缘即内容列左缘（现状已如此，固化并写进注释）。
**B5 任务页容器化**：TaskPanel 内容包一层 `max-width: var(--content-max)`（含「已选课时」区做成 settings-block 同款卡片容器，根治 D7）。
**B6 大标题基线**：`.content h2` 保持靠左，字号不变（这是现状唯一「靠左」做对了的元素）。
**B7 死规则清理**：清掉 B 批覆盖后残留的 `margin-inline:auto` 特例（grep 验证 0 残留）。

验收：四页签 + 导图在 1920/1440/1280 三宽度下左缘严格对齐（同一 x 坐标，截图 diff）；右侧留白一致无错位。ui-shots 双主题全量截图核对。

### 批 C：追问页身份与闭环（M2 + D3 + D4）

**C1 课时身份头部**：QaPanel 顶部嵌入 LessonChip（批 A 组件）：`「电子电路及系统I课程设计 · 第5节课」`，未选课时显示「未选择课时」占位。根治「不知道在问哪节课」。
**C2 提问回显**：submit 后立即将问题以 pending 气泡渲染（复用 qa-q 样式 + 加载点动画），answer 返回后原位替换为完整 pair。删除孤行「思考中…」。
**C3 气泡带时间戳**：qa:history 的 created_at 不再丢弃（app.tsx:691 的 map 补 created_at），气泡右下角小字时间（近 7 天显示相对时间「3 小时前」，更早显示日期）。QaEntry 类型 + 组件测试同步。
**C4 无笔记课时守卫**：hasLesson 且无笔记时输入框 placeholder 改「此课时尚无笔记——先生成笔记再追问效果更好」；提问照常放行（不门控，符合反门控偏好），但回答前 toast 一次性提示「该课时无笔记，回答基于空上下文」；qa:ask 的 assembleContext 无笔记时给模型 system 前缀注明「用户所选课时尚无笔记，请如实说明」。

验收：追问页顶部可见课时全名；提问后立刻看到自己的问题；历史气泡有时间；对无笔记课时提问有诚实提示。组件测试 +4（pending 气泡/时间戳/守卫提示/空态）。

### 批 D：思维导图折叠体验重做（M4）

**D1 折叠指示器重做**：废弃「尾部小圆徽标 + 文字省略号」，改为节点**右侧外挂 chevron 图标**（▸/▾ SVG 三角，与侧栏 caret 同语言），位置=分支延伸方向（视觉动线上）；折叠态节点右缘加 2px 强调色描边示意「这里有货」。
**D2 折叠计数徽标**：chevron 旁挂 `×N` 小胶囊（N=被折叠后代叶数，现有 childCount 逻辑复用），替代现在 8px 圆里的挤迫数字。
**D3 折叠过渡动画**：SVG 加 CSS transition（transform 过渡 200ms ease-out）。实现路径：布局保持「目标态」计算不变，节点 g 上叠 `transform: translate()` + transition；折叠时先动画后重排（或用 FLIP 技术：记录旧坐标→重排→反向位移→过渡到 0）。**若 FLIP 在 printToPDF/测试环境不稳，降级为 200ms opacity+scale 微动画，纯 CSS 零布局改动**——两条路线写进实现，先试 FLIP。
**D4 层级视觉编码**：depth 越深节点底色越浅/描边越淡（3 档 surface-2→surface→透明底+虚线边）；连线 stroke 透明度按 depth 递减（1.0/0.75/0.55）。纯 CSS，布局函数不动。
**D5 命中区扩大**：可折叠节点整盒可点保持，另加 chevron 圆形热区（r=14 命中区 > 视觉 r=8）。键盘语义不变（Enter/Space + aria-expanded 已有）。

验收：折叠一枝时其余节点不跳变（或平滑过渡）；折叠节点有明显 chevron+计数；三层节点一眼可分；导图视图双主题截图核对。MindMap 组件测试 +3（chevron 渲染/计数/热区）。

### 批 E：交互细节修缮包（D1/D5/D8/D11 + 遗留清单收尾）

- **E1** TaskPanel 裸 ID 根治随批 A（LessonChip 全名兜底；侧栏树找不到课时（被删课程）时才回退 ID，且加 title 说明）。
- **E2** 设置页「资料库与缓存位置」第三行拆分：笔记导出、日志各占一行（label+按钮一组，消灭四按钮排队）。
- **E3** 空态统一：QaPanel/NoteViewer 空态文案统一走 EmptyState 卡（msg 灰字保留给行内提示，页面级空态全卡片化）。
- **E4** 导出成功 toast 加动作按钮「打开目录」（ToastArea 支持 action 按钮，notes 三导出复用；打开的就是 exports 目录——现有 onOpenPath('exports') 通道直连）。
- **E5** 浅色 --text-muted 对比度微调：小字号场景（≤12px）升一档到 #5a6472（≈5.3:1），仅 hint/xs 字号作用域，全局 token 不动（避免大面积变色）。
- **E6**（顺手收尾历史遗留清单）②空态统一即③；「回车提交行为统一」「搜索防抖」批 C 已覆盖问答、侧栏搜索已有 debounce（app.tsx:522）——遗留清单核对后在 PROGRESS 注销。

### 批 F：键盘与效率（D9 + D10，可选批）

- **F1** Ctrl+1/2/3/4 切四页签（renderer keydown 监听，带 title 提示「Ctrl+1」）。
- **F2** 收藏星标正反馈：点击收藏后 toast「已收藏《课程名》」+ 星标填充态加深（现有样式调 contrast）。
- 本批独立可裁剪——Andiii 若觉得桌面效率键不重要可砍。

## 三、批次顺序与理由

| 批 | 内容 | 规模 | 理由 |
|---|---|---|---|
| A | 导航骨架（回首页+页头+LessonChip） | 中 | M1 主诉；LessonChip 是 C 批的前置组件 |
| B | 布局统一（单一内容列） | 小 | M3 主诉；纯 CSS 为主，最大视觉收益最快落地 |
| C | 追问页身份与闭环 | 中 | M2 主诉；依赖 A 的 LessonChip |
| D | 导图折叠重做 | 中大 | M4 主诉；独立于 A/B/C，动画有降级路线兜底 |
| E | 细节修缮包 | 小 | 审查发现集中收尾，多为几行改动 |
| F | 键盘与效率（可选） | 小 | 锦上添花，可裁剪 |

每批独立提交（Conventional Commits），批内 `npm run lint && typecheck && test` 全过再进下一批；涉及视觉的批（B/C/D/E）加 ui-shots 双主题截图自检。测试数只增不减。

**建议实施节奏**：A→B→C→E→D→F（把最大的 D 放在后半程，前面三批先把主诉 1/2/3 全部落地，Andiii 可先装机验收一轮再进导图重做）。

## 四、明确不做（本轮边界）

- 不做路由库/多窗口（面包屑+页头用现有 tab state 实现，零新依赖）。
- 不做笔记版本切换 UI、在线编辑器（遗留清单既有项，边界不变）。
- 不改笔记内容管线（prompt/Quiz/导出内容全部不动——本轮纯交互层）。
- 导图不换 markmap/d3 库（自绘 SVG 是 PDF 共用几何的根基，只做视觉与交互层增强）。
- 不做侧栏虚拟化/折叠（现状够用，另案）。

## 五、待 Andiii 拍板的决策点

1. **对齐系统总裁决**（批 B 全部的方向）：推荐**统一靠左 + 单一 860px 内容列**（导图破格全宽）——符合你「旧版协调感」的表述；反方案是「统一居中」（所有列水平居中，含任务页），若你其实想要居中请直说，工作量相同。
2. **左上角点击行为**：推荐「回到起始态（清课时选中+任务页）」；可选加强版「先弹确认」（不推荐——低破坏性操作不该有确认）。
3. **导图折叠动画**：推荐 FLIP 过渡（平滑）；保守版为纯 CSS 微动画（淡入缩放）；也可以无动画只要 chevron 重做。若嫌动画花哨可选保守版。
4. **批 F 是否要做**：Ctrl+数字切页签 + 收藏 toast，砍不砍？
5. **笔记卷头（试卷头）对齐**：批 B3 会把卷头从居中改靠左（与正文列一致）；若你想保留试卷头居中的「卷面仪式感」（正文列靠左、仅卷头居中），也可保留——推荐前者（全局一致），但这是审美裁决，你定。
