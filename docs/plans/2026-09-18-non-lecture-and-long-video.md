## 0. 结论先说

### 0.1 一句话结论

**能跑，但读起来是「课程笔记的形状硬套在访谈上」。**

导入这一侧**没有任何题材限制**——`bilibili/url-parse.ts:17` 只认 BV 号/链接，`ipc.ts:338-376` 的导入只检查付费/充电专属（`bilibili/pipeline.ts:30` `BilibiliPaidError`），不检查是不是课程。所以把一个 3 小时的访谈贴进去，今天就能出笔记。

问题全部在**产出侧**，分两类、彼此正交：

| | 问题 | 性质 | 影响面 |
|---|---|---|---|
| **题材** | note schema / prompt / 体检 / 视图 / 导出把「课堂讲授」写死在字段语义里 | **产品边界决策** | 访谈、脱口秀、播客、纪录片、测评 |
| **时长** | 生成是「全量转写一次入 prompt」，无预算、无分窗、无关键帧配额分摊 | **纯工程问题** | 所有 ≥2 小时的视频，**包括学习类**（公开课、学术讲座） |

**这两条必须分开处理**：题材那条要不要做是 Andiii 的定位决策（D1）；**时长那条无论 D1 怎么选都该做**，因为「学习视频」本身就有大量 2 小时以上的公开课与讲座。

### 0.2 题材失配：三类，按严重度排序

**① 主动编造类（最严重）——`methodology` 字段**

- `schema.ts:128` `methodology: z.string()` 是**必填**；视图侧 `views.ts:177` `methodologyBlocks` **无条件** push 一个「方法论分析」section。
- prompt `summarize.ts:46` 明确建议按「**解题思路 / 通用套路 / 易错点**」组织。
- 后果：一段单口喜剧会**必然**得到一节「方法论分析」，内容是模型为了填这个必填字段硬凑的。这不是「信息缺失」，是**生成假内容**——违背本产品「宁缺勿编」的核心纪律（`health.ts:5-6` 注释自陈）。
- 且它在 UI 上是一个**独立页签**（`labels.ts:35` → 「方法论」），用户一定会看到。

**② 空字段类（可接受但浪费）**

- `formulasAndSteps`（公式/代码/操作步骤）、`examCues`（考点）：访谈与脱口秀恒空。
- 已有守卫使其在视图与 markdown 里自动消失（`views.ts:147-148`、`markdown.ts:53-55`）——**这部分设计是对的**，无需改动。

**③ 结构缺口类——没有金句的地方**

- `Concept` 只有 `term/definition/example/refs`（`schema.ts:35-45`）；时间线条目是 `{at,title,detail}`（`:25-31`）。
- 访谈最有价值的内容是**原话本身**（「他说：……」，带时间戳）。今天它只能被模型塞进 `timeline.detail` 的自由文本里，与「这一段的描述」混在一起，无法单独读、无法单独导出。
- `quiz` 锚点只有 `concept | examCue`（`schema.ts:66`），`normalizeQuiz`（`:219`）把无锚点的题**直接丢弃**——脱口秀的自测题基本会被静默清空。

**④ 体检误判 → 花真钱**（这条是「③」的放大器）

- `health.ts:80-82`：`concepts.length === 0` → **warn**。访谈很可能确实没有「概念」。
- warn>0 会触发**一次额外返修调用**（`summarize.ts:434-453`），返修 prompt 同样是课程语义（`summarize.ts:236-243`）。
- 更贵的是：`NoteUpgradeDialog` 默认勾选 warn>0 的课时（agent 核实 `NoteUpgradeDialog.tsx:20-22`）→ **每次点「升级旧笔记」，这些访谈笔记都会被重新烧一遍钱，且结果不会变好**。

### 0.3 时长失配：三个硬约束

| 约束 | 位置 | 3 小时视频的实际后果 |
|---|---|---|
| **转写全量入 prompt，无任何预算守卫** | `summarize.ts:410` 直接拼 `inputs.transcriptText` | 见 §0.4 估算。**注意：`polish`/`qa` 都有 `MAX_TRANSCRIPT_CHARS = 24_000` 的抽稀守卫（`qa.ts:20,36`、`polish.ts:62`），唯独最贵的生成与返修两条是全仓仅有的无守卫调用点** |
| **图片预算固定 20 张** | `MAX_SUMMARIZE_IMAGES = 20`（`summarize.ts:28`） | 融合层在无 PPT 时会按时间均匀采样（`visual-fusion.ts:148-153`）→ 3 小时**平均 9 分钟一张画面**，画面证据基本失效 |
| **单次调用 10 分钟硬超时** | `CHAT_TIMEOUT_MS = 600_000`（`openai-client.ts:40`） | 转写越长、输出 JSON 越大，越可能撞上；**超时的结果是数小时算力全白烧**（没有部分产出） |

次要但真实的三条：

- **关键帧解码阻塞主进程**：`grid.ts:37` `decodeGrid8x8` 是**同步**的 `jpeg-js` **全分辨率**解码，且 `visual-hash.ts:52-62` 的 `buildVisualCandidates` 在 summarize 路径上对每一张关键帧都调用一次；`orchestrator.ts:632` 在抽帧路径上**再调一次**。3 小时 = 1080 张候选 → 约 2160 次同步解码。按 jpeg-js 解 640×360 约 20-40ms 估，**主进程会被阻塞数十秒**（推算，批 0 实测）——期间 UI 无响应。
- **无字幕走 ASR 的线性成本**：`audio-split.ts:23` 分片固定 120s → 3 小时 = **90 分片**，5 小时 = 150 分片。已有 checkpoint 续跑保护（`orchestrator.ts:560-566`），但时间与费用是线性叠加的。
- **B站流地址时效 100 分钟**（`resume.ts:25`）：单次连续下载通常够用；但下载中途失败后重试时，`urlsAreFresh` 会判定过期并**从 `fetching_course` 重来**——对长视频这是可接受的正确行为，不是 bug。

### 0.4 数字基础（真实库只读探针，2026-09-18 实测）

本机真实库只有一个 B站视频样本，实测：

```
bili-BV1vQMBz6EvP-P3 | bilibili | 73.5min | 1389 原始段 → 1125 清洗段 → 147 合流行 | 16531 字符 | 225 字符/分钟
```

按此速率外推（**推算，单样本，误差可能 ±40%**；B站字幕是秒级锚、`TIME_WINDOW_SECONDS = 30` 合流）：

| 视频时长 | 转写字符 | ≈ tokens（中文 1.3 字/token） | 关键帧候选（1/10s） | 无字幕时 ASR 分片 |
|---|---|---|---|---|
| 1 小时 | ~14k | ~11k | 360 | 30 |
| 2 小时 | ~27k | ~21k | 720 | 60 |
| 3 小时 | ~41k | ~32k | 1080 | 90 |
| 5 小时 | ~68k | ~52k | 1800 | 150 |

**读法**：3 小时的转写本身（32k tokens）多数 128k 上下文的模型能吃下，所以「跑通」不是问题。真正的问题是两个——**（a）质量**：一次成稿的长文必然「中间丢失」（模型对中段只能给出泛化概括，而这恰恰是长访谈的主体）；**（b）输出**：一份与 5 小时内容相称的笔记 JSON 会很大，撞上 `max_tokens` 截断即 JSON 解析失败 = 生成失败（`summarize.ts:473` 直接报错，无部分产出）。

### 0.5 本方案做什么、不做什么

**做**：批 0 长视频实测取证 → 批 1 素材层预算 → 批 2 题材语义（依 D1）→ 批 3 体检/视图自适应 → 批 4 长视频工程治理。

**不做**（与既有裁定一致，不重开）：
- 不重开教学/学习线（`note-craft/SKILL.md` §13，2026-09-17 Andiii 裁定）——本方案**不动 quiz**。
- 不为「非课程视频」新建第二套投影（`SKILL.md` §14 硬约束：`shared/notes/*` 是唯一投影源）。
- 不做跨课时聚合、不做云端、不做自动更新。
- **不承诺「适配所有视频题材」**——`DISCLAIMER.md:65` 已明写「不承诺适配所有课程或视频形态」，这条防线**继续保持**，本方案只提高实际质量，不新增承诺。

## 3. 批次设计

### 批 0：真实长视频实测取证（**不写产品代码**）

**为什么这是第一批**：本方案里所有关于长视频的结论目前都是**推算**（唯一实测样本是一个 73.5 分钟的视频）。本仓的纪律是「真实数据验收」，所以先把推算变成实测，再决定批 1/批 3 的取舍——**避免为一个想象出来的问题写代码**。

素材（三个，覆盖两个维度）：

1. **长 + 学习类**：一门 2 小时以上的 B站公开课/学术讲座（有字幕）——证明长视频问题**不只属于非课程题材**。
2. **长 + 访谈类**：2 小时以上访谈（优先有字幕；无字幕用 ASR 兜底，顺便量 90 分片的实际耗时）。
3. **中 + 娱乐类**：30-60 分钟脱口秀/单口——用短样本便宜地看清「题材失配」的实际观感（不需要等 3 小时）。

### 批 1：素材层预算（时长维度，**与 D1 无关，建议无条件做**）

1. 新增 `shared/notes/limits.ts`（唯一事实源）：`SUMMARIZE_TRANSCRIPT_BUDGET_CHARS = 30_000` + 关键帧分段配额函数。

## 5. 风险与纪律

| 风险 | 处置 |
|---|---|
| **分窗让统一性下降**（同一份笔记由 N 次调用拼出） | 段级中间物必须仍是**同一 schema 的子集**，归并是纯函数且有单测；禁止归并阶段让模型自由重写 |
| **引文可核验率回退** | 段级 `refs` 带 `at` 原样上抬；集成测试直接断言「分窗路径的可核验率 = 单次路径的水平」 |
| **成本上升**（分窗 = N+1 次调用；返修 = 再多一次） | 门槛设在 2.2 小时以上，多数视频仍是一次调用；批 3 堵住「无谓返修」这个浪费点 |
| **契约漂移** | 每批落钉住测试；`prompt_version` 按 `shared/notes/schema.ts:118` 的既有规则 +1 |
| **声明层漂移** | 本方案不新增用户可见承诺（D1=B 尤其如此）。**若 D1=A**，导入对话框的形态选择属新界面 → 按 AGENTS「声明层纪律」先改 spec §2/§5，再落实现 |
| **零回归** | 批 1 的门槛以下路径、批 2 的可选字段默认值，都必须有「短转写 / 存量笔记行为逐字节不变」的断言 |

**测试纪律**（AGENTS 硬规定）：测试数只增不减；不得 skip/mock 被测关键路径来制造绿灯。

1. **批 0（实测）先行**——成本低、信息量大，且能纠正我这里的推算误差。**没有它，批 1 的设计参数（门槛取值、分段粒度）就是在猜。**
2. **批 1（素材层预算）+ 批 4-1（关键帧解码）**——纯工程、零产品边界争议、且**对所有长视频都有效**（包括学习类）。
